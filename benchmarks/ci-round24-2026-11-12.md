# Reusing inline source reads, November 12, 2026

Source preparation previously walked and read every selected snapshot to find
runtime store references, then walked and read small snapshots again to encode
them. The encoder now reports the complete file bytes it already reads, allowing
reference scanning to share those reads. This leaves compression, inline limits,
source selection and replay scripts unchanged.

A rejected inline candidate may have read only some files. Such snapshots still
receive a full reference scan, including files beyond the size or compressed
payload limit. References are collected before encoded source payloads replace
source tokens, and only selected snapshots contribute runtime dependencies.

Baseline `ee0e3c4` has the same tree as merged main `41e25a2`; implementation
`8de6eb9` contains the code, tests and callback-contract comment.
[Raw measurements and validation](ci-round24-2026-11-12.json) accompany this report.

## Standalone export

Seven alternating pairs plus warmups run each workload with two and four Go
threads. The same `GOMAXPROCS` setting reaches exporter and Go discovery
subprocesses. This measures export and existing-output replacement with warm
SDK/filesystem caches; it excludes Nix evaluation and package builds.

| Workload | Go threads | Before | After | Change |
|---|---:|---:|---:|---:|
| fixture | 2 | 0.174 s | 0.172 s | -1.2% |
| upm-prepared | 2 | 0.498 s | 0.488 s | -1.9% |
| fixture | 4 | 0.168 s | 0.169 s | +0.6% |
| upm-prepared | 4 | 0.451 s | 0.441 s | -2.2% |

UPM export improves by about **2%**, saving roughly 10 ms. The fixture results
are effectively flat. All 64 exports preserve graph JSON, evaluation JSON,
rendered scripts and resolved toolchain metadata. A complete comparison of the
final exports also matches every file: 732 for the fixture and 3,167 for UPM.

## Complete cached CI

Seven alternating pairs plus warmups cover both workloads and nested evaluators.
All 64 builds preserve the same package output as their baseline. Each distinct
fixture or UPM executable is also run successfully.

| Workload | Nested evaluator | Before | After | Change |
|---|---|---:|---:|---:|
| fixture | nix | 0.869 s | 0.867 s | -0.2% |
| fixture | iets | 0.672 s | 0.659 s | -2.0% |
| upm-prepared | nix | 2.512 s | 2.488 s | -1.0% |
| upm-prepared | iets | 2.057 s | 2.053 s | -0.2% |

The differences are small, from 0.2% to 2.0% faster, with mixed changes in the
individual evaluation/realization phases. Treat full cached CI latency as
effectively unchanged; the clearer result is the standalone UPM exporter gain.

Each run forces fresh dynamic planning, with warm tools and Go package outputs.
The outer client is Nix. Nested iets uses static upstream PR #3 at
`69883a64bfb0d9a95dce253dae304878e07b076e`, one worker, caches disabled and fallback
forbidden. Sandboxing is enabled without fallback, IFD and substitutions are
disabled, and Nix uses four jobs/two cores. UPM is revision
`35a76c282507fb942445c0ee98427b3d1ef772bc`, package `./cmd/upm`, with the same
prepared module cache for both revisions. The Go SDK is 1.26.5.

## CLI bootstrap and planner payload

Five alternating pairs plus warmups force twelve fresh CLI package builds with
fresh Go caches and warm SDK/filesystem caches. Each includes all unit tests and
vet, with strict sandboxing, no IFD/substitutions and Nix four jobs/two cores.

Median evaluation plus realization is **6.169 s before and 6.186 s after**
(+0.3%), effectively unchanged. Each revision has a stable installed NAR
across all six builds. The CLI grows from 3,387,216 to 3,391,312 bytes, and both
retain only the same tzdata runtime reference. CLI binary bytes change.

| Evaluator | Paths, unchanged | Before NAR bytes | After NAR bytes | Before zstd bytes | After zstd bytes |
|---|---:|---:|---:|---:|---:|
| nix | 958 | 324,520,928 | 324,527,528 | 93,735,738 | 93,736,347 |
| iets | 900 | 210,363,592 | 210,370,192 | 54,826,447 | 54,827,056 |

Complete planner input closures grow by **6,600 NAR bytes and 609 compressed
bytes**, including raw derivation metadata. Compiler, linker, native and full
worker toolchains remain identical. Generated package outputs and their cache
keys are unchanged. Payloads come from fresh local zstd-level-3 binary caches;
there is no network-transfer timing claim.

## Validation and another discovery lead

Unit tests and vet pass. Added tests retain references at EOF in the last file
for raw, compressed, size-rejected and payload-rejected snapshots, reject
truncated overlong references, and check the intended inline selection. Existing
tests cover parallel determinism, source order, invalid queries, restricted
recursive stores, missing snapshots and failure before graph mutation.

The full Go 1.26.5 compatibility and iets suites pass, including native assembly,
cgo/C++, race, stripped/debug-preserving builds, compact archive modes, runtime
references, optional-test validation, source edits and previous-plan reuse.
Linux x86-64, Linux ARM64 and macOS ARM64 across all three supported SDKs remains
the merge gate.

A separate capability probe tested `go list -deps -export -n` as a possible
replacement for the parallel list/build discovery commands. All three supported
SDKs emit package metadata and compiler actions, but **no root linker action**;
ordinary `go build -n` emits one. The Go driver explicitly skips linking in list
mode. That direct substitution cannot produce drvgo's executable graph and was
not applied. The JSON records all six commands and action counts.
