# Smaller GCC inputs for native workers

The Linux amd64 native worker tool closure drops from **137.62 MB to 121.36 MB
compressed**, saving **16.26 MB (11.8%)**. The change removes GCC's `lto-dump`
inspector while retaining its C/C++ frontends, LTO backend, libraries, headers,
and diagnostics. Darwin and non-GNU compiler selections are unchanged.

This is a download-size improvement. Cached CI medians range from unchanged
to 2.2% slower. Preparing an uncached compact compiler adds about **0.98 s**
with compiler and build inputs already available; CLI bootstrap stays flat.

Measurements compare `42fca304949171c897f7aee91d02c186d6896871` with
`84fb66b4df275bb198071e6fde0f198bdb536cbf`, using Go 1.26.5, GCC 15.3.0, the
repository's pinned Nixpkgs, and iets PR #3 at
`69883a64bfb0d9a95dce253dae304878e07b076e`. [Measurements and validation
evidence](ci-round28-2026-11-12.json) include individual samples, commands,
store paths, hashes, and affected package recipes. Sizes are decimal MB from
local zstd level 3 binary caches; network transfer time was not measured.

## Compiler preparation

`lto-dump` inspects compiler intermediate representation. Actual LTO compilation
uses `lto1`, which remains available. The compiler driver and frontends also
remain necessary for Go's external-link flag probes.

The builder copies the pinned GCC output, removes the inspector, and relocates
embedded references by replacing only the fixed-length store hash. The output
keeps its original basename, and a length assertion guards the replacement.
`disallowedReferences` rejects any remaining dependency on the original compiler.
The compiler wrapper uses the current build environment. This requires neither
a GCC rebuild nor a Python dependency nor a separate bootstrap environment.

All **1,651 retained regular files** were compared with the original compiler.
Eighteen contain relocated references; their bytes match after normalizing only
the exact old/new compiler prefix. All other files match without normalization;
executable bits and symlinks also match. Only `bin/lto-dump` is removed from this
pin. Store queries confirm that neither the original compiler nor its wrapper
remains in the native worker's closure.

The original compiler is still needed to construct this copy when it is absent
from the binary cache. Workers downloading a cached compact toolchain avoid that
input. Native preparation is separate from dynamic planning, which only carries
the corresponding derivation metadata.

## CI and preparation time

Each cached-CI case uses seven interleaved measured pairs and a warmup pair:
**64 builds total**. Every build has a fresh planner and warm tool/package
outputs. Sandboxing is required, IFD and substitution are disabled, and these
measurements run sequentially after validation finishes. Sources and explicit
build IDs are fixed. UPM uses the same prepared module cache in both revisions.

| Workload / nested evaluator | Before median total | After median total | Change |
| --- | ---: | ---: | ---: |
| Fixture / Nix | 0.853 s | 0.872 s | +2.2% |
| Fixture / iets | 0.665 s | 0.678 s | +2.0% |
| UPM / Nix | 2.457 s | 2.485 s | +1.1% |
| UPM / iets | 2.062 s | 2.061 s | -0.03% |

There is no demonstrated cached-CI speedup. Evaluation medians increase by
roughly 5–9 ms. Package output paths remain stable within each revision and
agree between Nix and iets; command behavior agrees across revisions.

Fresh reproducibility-checked builds of the two preparation steps use one
warmup and five measured runs each. Median times are **0.685 s** for the GCC
copy/prune/relocation and **0.293 s** for the compiler wrapper. Their sum is
approximately 0.978 s. Inputs are cached, and these timings include Nix startup
and reproducibility checking; they exclude downloading the original compiler.

Twelve fresh CLI builds, including all unit tests and vet, yield median totals
of **6.245 s before and 6.251 s after** (+0.1%). Both stripped CLIs are 3,403,600
bytes. Each revision produces repeatable binary and NAR hashes; the revisions
differ because the CLI embeds the changed toolchain recipe.

## Cache effects and validation

- Pure-Go assembly exports, including explicit internal links, keep all 62
  package recipes. Native changes invalidate 4/67 fixture recipes, 164/554 UPM
  recipes, 4/72 net recipes in both automatic and internal modes, and 5/74 race
  recipes. Source hashes and replay scripts stay identical in every comparison.
- Fixture, C++, race, and UPM commands were built with both toolchains in debug
  and stripped modes under strict sandboxing. All eight cases have identical
  behavior and runtime store references. All four stripped executables are
  byte-identical. Unstripped outputs may contain the relocated compiler prefix
  in debug data; all four become byte-identical after removing debug sections.
- New required compatibility coverage compiles and executes C and C++ programs
  both normally and with `-flto`, including C++ standard-library use and
  exceptions. All four variants pass. The existing four internal-link variants
  also pass their comparison against the complete native bundle.
- Unit tests, normal/integration vet, and the full local Go 1.26.5 compatibility
  suite pass: 17 differential cases plus cache invalidation, hermetic replay,
  custom build IDs, race/test binaries, empty tests, runtime references,
  previous-plan reuse, and dynamic builds with IFD disabled.
- The complete iets PR #3 suite passes outer/nested evaluation and builds,
  direct `outputOf`, the flake helper, stripped/debug-preserving links,
  internal links with/without race instrumentation, optional/native tests,
  runtime references, and source invalidation. Classic fallback and the tracing
  cache are disabled. Its single timing trial is used for correctness only;
  the separate cached-CI measurements above provide repeated timing samples.

The full Linux amd64/arm64 and Apple Silicon compatibility matrix across all
three pinned Go SDKs must pass before merging. The new GCC-specific test skips
Darwin and non-GCC compilers, whose toolchain construction is unchanged.
