# Stripped CLI bootstrap, November 11, 2026

The packaged CLI no longer generates compiler DWARF data that its installed
executable does not retain. It also links with `-s -w` to omit linker symbol and
debug tables. Go's runtime function/line tables remain present for stack traces.
This affects the Nix-packaged CLI; ordinary source builds and generated package
compiler flags are unchanged. Implementation `9a27714` is compared with
`fb75fa1`, whose tree is identical to the preceding merge on main.
[Raw results and validation](ci-round22-2026-11-11.json) accompany this report.

## Fresh CLI builds

Five alternating trials plus one warmup per revision force twelve fresh Nix
package builds. Each includes all unit tests and vet, with a fresh Go cache,
warm SDK and filesystem caches, two Nix build cores and four jobs. Substitutions
and IFD are disabled; sandboxing is enabled without fallback.

| Measurement | Before | After |
|---|---:|---:|
| Median evaluation + realization | 6.518 s | 6.192 s |
| Median realization | 6.274 s | 5.955 s |
| Installed CLI bytes | 3,661,000 | 3,387,216 |

Bootstrap improves by **5.0%**, and the installed executable is **7.5% smaller**.
Each revision produces a stable installed NAR across all six builds. Binary bytes
change as expected, and both retain exactly the same tzdata runtime reference.
The executable's `.symtab` and `.strtab` disappear; `.gopclntab` retains its
1,265,084-byte size. This is not a claim that executable sections are byte-identical.

Isolated test subprocesses use the test executable's recorded trimpath and
supported compiler-DWARF settings, preserving cache reuse without forwarding
ambient Go settings. An initial compiler-only experiment omitted this matching
and rebuilt the standard library in tests: 6.476 s became 8.822 s. Matching the
settings reduced the compiler-only result to 6.238 s versus 6.519 s. The final
measurements above include matching test settings and linker stripping.

```sh
python3 scripts/benchmark-bootstrap.py \
  --before /path/to/baseline --after /path/to/current \
  --nixpkgs /path/to/pinned-nixpkgs --runs 5 --cores 2 --jobs 4
```

These timings exclude SDK downloads, cold filesystem caches and network transfer.
The pinned SDK is Go 1.26.5 from Nixpkgs
`6b5e5b7a6631f065bf6908986990b37d845f847f`.

## Complete cached CI

Seven alternating trials plus warmups cover eight fixture/UPM configurations,
forcing fresh dynamic planners with warm tools and compiled Go outputs. All
128 builds preserve their baseline package output. Nix uses four jobs and two
cores; sandbox fallback, IFD, substituters and forced substitutions are disabled.
Nested iets is static upstream PR #3 at
`69883a64bfb0d9a95dce253dae304878e07b076e`, with one worker, caches disabled and
fallback forbidden.

| Workload | Nested evaluator | Before | After |
|---|---|---:|---:|
| fixture | nix | 0.858 s | 0.856 s |
| fixture | iets | 0.657 s | 0.665 s |
| upm-proxy | nix | 3.386 s | 3.365 s |
| upm-proxy | iets | 2.998 s | 3.008 s |
| upm-prepared | nix | 2.474 s | 2.492 s |
| upm-prepared | iets | 2.048 s | 2.059 s |
| upm-previous | nix | 1.311 s | 1.309 s |
| upm-previous | iets | 1.168 s | 1.180 s |

The range is 0.6% faster to 1.2% slower: treat cached CI latency as effectively
unchanged. The improvement is fresh CLI bootstrap and executable size. UPM is
revision `35a76c282507fb942445c0ee98427b3d1ef772bc`, package `./cmd/upm`; commands,
inputs, per-trial timings and output paths are recorded in the JSON.

Both complete closures lose 273,496 NAR bytes and **62,230 compressed bytes**.
The measurement uses fresh local zstd-level-3 binary caches, including raw
recipe metadata; it does not measure network latency. Compiler, linker, native
and full worker toolchain derivations remain identical. No extra dependency or
reusable cache input is introduced.

## Validation and source-pruning checks

All twelve final bootstrap builds pass unit tests and vet. The full Go 1.26.5
compatibility suite uses the measured Nix-built CLI and passes differential
native assembly, cgo/C++, race, tags, linking, workspaces, vendoring, module-cache
checks, runtime references, restricted-store errors and dynamic invalidation.
The full iets suite passes outer/nested evaluation, direct dynamic outputs,
public helper use, optional tests, runtime references and previous-plan reuse.
Platform/SDK CI remains the merge gate.

A separate read-only investigation considered shrinking the SDK source tree.
The selected SDK has about 51 MB under `src/cmd`, and 17 MB of `_test.go` files
across its sources. Neither is generally safe to remove. Synthetic mismatched
package names and malformed test imports make ordinary `go list -deps` fail;
deleting the test file hides those errors. There are also 42 currently eligible
non-main packages under public `cmd` subdirectories. A project importing
`cmd/cover/testdata/pkgcfg/noFuncsNoTests` loads successfully with the full tree
and fails when `src/cmd` is absent. The JSON retains these counterexamples.
No SDK source pruning was applied.
