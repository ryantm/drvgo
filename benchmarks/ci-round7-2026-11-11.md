# Reuse cgo builds after checkout or module-cache relocation

Measured on Linux amd64 with Go 1.26.5 on November 11, 2026. The baseline is
`4ee5e078ad2e8365b0f9673493db8183fce8ebf2`, merged through PR #13. The implementation
is `e4bd708`. [Raw samples and validation evidence](ci-round7-2026-11-11.json)
include every timing sample, recipe comparison, closure measurement, and the UPM
validation probe. Timing benchmarks ran sequentially, without other local build
or compression work. Integration timings are excluded from performance claims.

## Cache reuse

Go's dry run incorporates absolute paths into automatic action IDs for cgo flags
such as `#cgo CFLAGS: -I.`. Identical source at a different checkout or module-cache
location therefore produced different package recipes even after drvgo normalized
the actual compiler inputs.

The exporter now removes automatic compiler/linker IDs. The native worker derives
replacement action IDs from the Nix-resolved recipe and toolchain/environment,
before substituting temporary paths or CPU budgets. Link IDs include the main
archive's actual build ID. Content-ID updates and Mach-O signing still use the
selected SDK's implementation. Explicit custom and empty IDs are preserved.

Five alternating trials copy an identical 63-package cgo command to a second
directory after building it in the first. Each revision/trial uses a unique
module path, so another trial cannot supply the initial application output.
The command and its native subpackage both use relative include flags and headers.

| Second-location measurement | Before | After |
| --- | ---: | ---: |
| Export + evaluation + realization | 0.992 s | 0.275 s |
| Export | 0.186 s | 0.187 s |
| Evaluation | 0.074 s | 0.060 s |
| Realization | 0.729 s | 0.029 s |
| Changed package recipes | 2 | 0 |
| Package builds | 2 | 0 |

The second build is **72.3% faster** in this fixture. All unchanged package recipes
and the final output now match across locations. Each binary is run and checked.
Warmup is excluded, strict sandboxing and IFD-disabled evaluation are enabled,
and remote cache lookups are disabled. Builds use four jobs and two cores.

Pinned UPM (`35a76c282507fb942445c0ee98427b3d1ef772bc`, 554 packages) now produces
the same output through all three paths:

- Default dynamic planning with fresh extraction from the fixed module proxy.
- Dynamic planning with `prepareModules = true`.
- Standalone export using the prepared module cache.

Previously, default proxy extraction and prepared-cache planning produced
different outputs. The UPM binary passes `--version` and `list-languages`, and
the prepared cache is absent from its runtime closure. This is an output-identity
check; it is not a cold-store timing measurement. Module preparation stays opt-in.

## Existing workload costs

Five alternating trials, fresh planners with tools and package outputs available:

| Default UPM dynamic build | Before | After |
| --- | ---: | ---: |
| Evaluation + realization | 3.433 s | 3.439 s |
| Outer evaluation | 0.411 s | 0.407 s |
| Realization | 2.994 s | 3.030 s |

The default steady CI case is effectively unchanged. Separately, recompiling all
67 packages in the embedded-file/cgo fixture with `nix-build --check` takes
**4.129 s before and 4.114 s after** (five alternating trials, warmup excluded).
This includes all compiler/linker work and verifies reproducible outputs within
each revision. It excludes downloads and cold-tool setup.

Already-exported UPM graph evaluation, 15 alternating measured trials:

| Evaluator | Before | After |
| --- | ---: | ---: |
| Nix | 135.0 ms | 134.7 ms |
| iets PR #3, one worker | 41.4 ms | 42.9 ms |
| iets PR #3, four workers | 58.3 ms | 58.4 ms |

The iets revision is `69883a64bfb0d9a95dce253dae304878e07b076e`. Tracing cache and
fallback are disabled. All evaluators return the same derivation for each graph.
These results do not show an evaluation speedup from the build-ID change.

## Transfer cost and compatibility

The worker closure gains **8,192 NAR bytes**, or **3,577–3,578 zstd level 3 bytes**,
with no extra paths. Compile/link/native closures remain 4/9/42 paths. The CLI
closure gains 8,424 NAR bytes and 2,086 compressed bytes, remaining at two paths.
Measurements sum complete closures copied to a local binary cache; they do not
measure remote download latency.

The worker recipe changes once, so existing package outputs require rebuilding
or substitution under the new recipes. Automatic IDs can differ from cmd/go's
IDs. Custom IDs, empty IDs, native archive handling, runtime references, and SDK
content hashing remain supported.

Validation includes unit tests and vet; the complete Go 1.26.5 compatibility and
iets suites; source relocation, custom IDs, native reproducibility, and compressed
native sources under Go 1.25.12, 1.26.5, and 1.26.6; and offline module-cache tests
covering relocation and fresh proxy extraction. Native reproducibility varies
temporary directory, physical/symlink paths, and one versus four worker cores.
An unrelated import preserves existing dependency recipes; a header edit changes
only its package and the application. Recorded trace changes were audited before
updating hashes: only automatic ID removal and the compile/link wrappers differ.
The platform matrix exercises Linux amd64, Linux arm64, and Apple Silicon.

## Reproduction

```sh
python3 scripts/benchmark-relocation.py \
  --before-drvgo /path/to/baseline-drvgo \
  --after-drvgo /path/to/new-drvgo \
  --before-toolchain /nix/store/baseline-toolchain \
  --after-toolchain /nix/store/new-toolchain --runs 5

python3 scripts/benchmark-ci.py \
  --before /path/to/baseline-checkout --after . \
  --source /path/to/pinned-upm --package ./cmd/upm \
  --vendor-hash 'sha256-A4CU4C5SmEZP6Q+CVHjp+Jy4UxRXAnpvhzrsdq4NlsM=' \
  --nix-option sandbox true --nix-option substituters '' \
  --nix-option always-allow-substitutes false --runs 5

python3 scripts/benchmark-evaluation.py \
  --before /path/to/baseline-upm-export --after /path/to/new-upm-export \
  --iets /path/to/iets-pr3/bin/iets --runs 15

python3 scripts/benchmark-build.py \
  --before /path/to/baseline-embed-cgo-export \
  --after /path/to/new-embed-cgo-export --runs 5

python3 scripts/benchmark-closure.py \
  --before /nix/store/baseline-toolchain --after /nix/store/new-toolchain
```
