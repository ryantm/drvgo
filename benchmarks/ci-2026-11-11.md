# CI optimization measurements, November 11, 2026

Compare `b429c14` with implementation `9c675f5`, on Linux amd64, an Intel
i7-1280P, Go 1.26.5, and Determinate Nix 3.24.1 / Nix 2.35.3.
[Raw samples, commands, store paths, and validation](ci-2026-11-11.json) accompany
these results. Timings alternate before/after order and exclude warmups.

| Workload | Before | After | Change |
|---|---:|---:|---:|
| Rebuild all 1,061 synthetic package units, 5 trials | 31.744 s | 21.048 s | 33.7% faster |
| Rebuild all 67 fixture units, 7 trials | 4.316 s | 4.138 s | 4.1% faster |
| Export + evaluate 1,061 units, 9 trials | 0.683 s | 0.667 s | 2.3% faster |
| Dynamic CI: fresh planner, cached package outputs, 7 trials | 10.699 s | 10.887 s | 1.8% slower |

Rebuilds request **every unit** with `nix-build --check --max-jobs 4 --cores 2`,
so they check reproducibility as well as recompilation. Tools, sources, and
dependency outputs are already present. These are not cold-store timings.
The synthetic module contains 1,000 small packages with dependencies on the
previous package and packages 10 and 50 positions earlier; its main command
also imports `fmt`. It is a build workload, not a runtime benchmark.

| Toolchain role | Before NAR | After NAR | Before zstd | After zstd |
|---|---:|---:|---:|---:|
| Compile/assembly | 292.2 MiB | 35.8 MiB | 81.5 MiB | 11.8 MiB |
| Pure Go link | 618.0 MiB | 78.2 MiB | 182.9 MiB | 25.0 MiB |
| Native/cgo | 618.0 MiB | 431.2 MiB | 182.9 MiB | 135.5 MiB |
| Planning | 618.0 MiB | 652.4 MiB | 182.9 MiB | 194.9 MiB |

These are complete toolchain closures. The compile closure has four store paths,
down from 21. Compressed sizes sum a local binary cache's zstd level 3 payloads;
they do not measure a network. Per-package source snapshots and dependency
archives are additional inputs. Standard-library snapshots replace workers'
dependency on the entire SDK. The local planner retains the SDK and copied
worker tools, which increases its closure by 5.6%.

## What changed

- The native runner replaces shell startup, text substitution, and file-operation
  subprocesses in each package action. It links the selected Go release's
  build-ID implementation through a build-time source overlay, avoiding another
  process per package while retaining Go's hash and Mach-O signing behavior.
- Compile, link, and native bundles carry only their required tools. Compiler,
  assembler, linker, and cgo executables remain the selected SDK's binaries.
- Standard-library sources and their local quoted includes are snapshotted per
  package. Snapshots copy and NAR-hash the same bytes in one pass.
- Argument normalization uses byte checks instead of regular expressions in its
  hot path. Path rewriters and output buffers are reused. Diagnostic JSON is
  compact; `jq . graph.json` formats it for inspection.

Debug information and package cache granularity are preserved. New recipes cause
a one-time rebuild; ordinary and dynamic exports continue sharing package outputs.

## iets and the remaining planning cost

Tested replit/iets PR 3 at `69883a64bfb0d9a95dce253dae304878e07b076e` with
classic fallback and IFD disabled. Outer and nested planning, direct `outputOf`
builds, repeat builds, and embedded-file invalidation pass.

| Warm evaluation, 7 trials | Nix | iets, 1 worker | iets, 4 workers |
|---|---:|---:|---:|
| Exported 1,061-unit graph | 154 ms | 55 ms | 78 ms |
| Dynamic fixture wrapper | 392 ms | 190 ms | 106 ms |

Tracing caches are disabled; iets's compiled-file cache is warm. Each evaluator
produces the same derivation path for a given graph. These workloads differ:
the dynamic wrapper evaluates nixpkgs, while an existing export uses its resolved
toolchain. More workers are not always faster.

Fresh dynamic CI with cached packages remains roughly flat. One diagnostic run
spent 0.29 s exporting and 3.18 s in recursive `nix-instantiate`; the remaining
realization time was not attributed. Disabling planner substitution did not
improve four alternating trials, so planner caching remains enabled.

Follow-up: the [next round](ci-round2-2026-11-11.md) traced the unattributed time
to remote cache queries and found `always-allow-substitutes=true` on the test
machine. That setting overrode the planner-substitution experiment above.
The follow-up measures store/evaluator work separately from metadata latency.

Other options examined:

- Rebuilding `cmd/link` without cgo did not remove its libc closure: the pinned
  linker embeds Nix's ELF loader configuration. Keep the original linker.
- Pruning the planning SDK complicates ordinary Go tooling and standalone
  recovery. The worker bundles provide the large size reduction without it.
- Stripping dependency debug data, merging package derivations, or broadly pruning
  arbitrary native auxiliary files would change debugging, cache granularity,
  or supported includes. Those tradeoffs are not enabled by default.

## Validation and reproduction

[All 11 implementation CI jobs passed](https://github.com/ryantm/drvgo/actions/runs/43047741523):
Go 1.25.12, 1.26.5, and 1.26.6 on Linux amd64, Linux arm64, and macOS arm64,
plus Linux and macOS package checks. Coverage includes assembly, cgo, C++,
explicit external links, Darwin frameworks, race detection, test binaries,
cache invalidation, standalone recovery, and dynamic builds with IFD disabled.
The harness now rejects an integration binary built without its integration tag.

The 554-package UPM command at `35a76c282507fb942445c0ee98427b3d1ef772bc`
builds in the sandbox and passes `--version` and `list-languages` smoke tests.
All 67 fixture outputs were also unchanged after applying the original pinned
`cmd/buildid` tool to the native runner's results.
