# Dynamic CI planning, November 11, 2026 — second round

Baseline: `16c8ce9`. Optimization: `64a84f6`; `4fb413b` adds an opt-in for planner
substitution without changing its default recipes. Measurements use Linux amd64,
an Intel i7-1280P, Go 1.26.5, and Determinate Nix 3.24.1 / Nix 2.35.3. The normal
recursive planner uses the pinned Nix 2.34.8. Trials alternate before/after order
and exclude warmups. [Raw samples and validation](ci-round2-2026-11-11.json)
accompany this report.

## Results

Fresh dynamic planning of the 1,061-unit synthetic graph with compiled packages
already cached fell from **3.768 s to 2.423 s (35.7%)**, over five trials with
remote cache queries disabled on both revisions. Outer evaluation stayed at
about 400 ms; realization, including recursive planning and forwarding, fell
from 3.370 s to 2.009 s. This isolates the implementation improvement from cache
service latency. It is not a cold-store or network-transfer benchmark.

| Workload | Before median | After median |
|---|---:|---:|
| Fresh dynamic CI, 1,061 units, local queries only | 3.768 s | 2.423 s |
| Fresh dynamic CI, 67 units, local queries only | 0.928 s | 0.901 s |
| Rebuild all 1,061 units | 20.827 s | 20.882 s |
| Rebuild all 67 units | 4.113 s | 4.137 s |
| Export + evaluate 1,061 units | 0.655 s | 0.632 s |
| Export + evaluate 67 units | 0.405 s | 0.414 s |
| Export + evaluate UPM, 554 units | 0.696 s | 0.712 s |

Rebuild timings are essentially flat (+0.3% and +0.6%). Small-graph and UPM
standalone export timings are also roughly flat; this change primarily targets
recursive evaluation of graphs with many small packages.

The synthetic module has 1,000 small packages, each depending on preceding
packages at offsets 1, 10, and 50, plus a command importing `fmt`. It is a build
workload, not a runtime benchmark. The 67-unit fixture includes embedded assets
and cgo. UPM is the 554-unit command at
`35a76c282507fb942445c0ee98427b3d1ef772bc`; its standalone export uses an offline
module proxy and selects `cmd/upm` as its working directory.

Rebuild measurements request every unit with `nix-build --check --max-jobs 4
--cores 2`. Tools, sources, and dependency outputs are warm. These also check
reproducibility. Compilation speed is not the source of the large CI gain.

## Why it helps

A syscall trace of recursive evaluation attributed 2.676 s of waiting to
`read`, versus only about 61 ms of total kernel CPU time in an earlier trace.
The evaluator registers sources and derivations serially through the restricted
recursive store. Parallel source preloading helped only modestly: a diagnostic
run improved source registration from 1.49 s to 1.05 s with eight evaluator
processes, while derivation registration still took about 1.6 s. That approach
was not retained.

Snapshots costing at most 4 KiB, including filenames and metadata, now travel
as base64 in the existing file-backed replay script. The native builder restores
the bytes and executable modes before invoking the unchanged compiler tools.
Larger snapshots retain their separate store objects. The cutoff bounds recipe
growth and avoids copying large sources into each build directory.

| Graph | Separate source objects before | After | Replay script bytes before | After |
|---|---:|---:|---:|---:|
| Synthetic | 1,061 | 42 | 854,384 | 1,209,185 |
| Fixture | 67 | 44 | 108,694 | 182,025 |
| UPM | 554 | 400 | 790,286 | 1,232,823 |

Small files are still retained in the portable export for inspection.
Evaluation metadata omits their unused store-source hashes. The runner adds
**8,192 NAR bytes** to each toolchain closure and no additional store paths;
the compile closure remains about 35.8 MiB. Package granularity, debug data,
compiler selection, and ordinary/dynamic output sharing remain intact. The
updated runner changes recipes, causing a one-time package rebuild.

## Cache metadata is a separate cost

The first profiling run spent several seconds querying eight configured caches
for planner/forwarder paths. This machine has `always-allow-substitutes=true`,
which [overrides derivation-level substitution hints](https://nix.dev/manual/nix/2.35/command-ref/conf-file#conf-always-allow-substitutes).
This explains why the previous round's attempt to disable planner substitution
appeared ineffective. No machine configuration was changed.

With remote caches enabled and `always-allow-substitutes=false` supplied equally
to both revisions, five-trial medians were **12.285 s → 2.410 s**. With the
machine's inherited override, three-trial medians were **10.423 s → 9.494 s**.
These network-dependent runs are diagnostics, not portable speedup estimates.
Cache latency varied substantially between trials and batches.

The planner now defaults to `allowSubstitutes=false`, like the forwarding
outputs. Generated Go packages retain normal substitution and remote-build
support. For changing-source CI, this avoids queries for a fresh planner and
recomputes its derivation/source closure locally. If a cache explicitly publishes
planner outputs and identical-source reruns on cold workers are common,
`allowPlannerSubstitutes=true` restores that option and can avoid downloading the
planning SDK. Setting the global `always-allow-substitutes=true` also overrides
forwarder hints; the narrower package option is preferable for that use case.

Removing the inner forwarding derivation was also tested and rejected: Nix
correctly rejects a generated `.drv` whose output name does not match the
text-addressed planner output. Both wrappers remain.

## iets and validation

Tested [replit/iets PR 3](https://github.com/replit/iets/pull/3) at
`69883a64bfb0d9a95dce253dae304878e07b076e`, with IFD, classic fallback, and
tracing caches disabled. Outer and nested planners, direct `outputOf` builds,
repeat builds, embedded-file invalidation, and equality with Nix all pass.

| Exported 1,061-unit graph, 7 trials | Before | After |
|---|---:|---:|
| Nix | 155 ms | 118 ms |
| iets, 1 worker | 56 ms | 35 ms |
| iets, 4 workers | 73 ms | 52 ms |

These are warm graph evaluations, with iets's compiled-file cache warm.
They exclude discovery, realization, and network transfer. The separate dynamic
fixture wrapper still takes about 401 ms in Nix, 198 ms in iets with one worker,
and 108 ms with four workers; the outer wrapper itself is essentially unchanged.

Unit tests cover binary and empty source files, quoted filenames, executable
modes, invalid encodings, the size boundary, and package-local invalidation.
Integration tests grow an embed across the cutoff and shrink it back, require
exactly two affected units, and verify restoration of the original recipes.
The existing suite checks relocated standalone exports, source removal,
assembly, cgo, C++, external linking, build tags, vendoring, workspaces, test
binaries, race detection, and dynamic builds with IFD disabled.

Local Go 1.26.5 compatibility and integration checks pass. The UPM command also
builds in the sandbox and passes `--version` and `list-languages` smoke checks.
An explicit policy check confirms that adding `allowPlannerSubstitutes` preserves
the default derivation path and that both policy settings resolve to the same
output. The [CI matrix](https://github.com/ryantm/drvgo/actions/runs/43059966105)
covers Go 1.25.12, 1.26.5, and 1.26.6 on Linux amd64, Linux arm64, and Apple
Silicon macOS, plus Linux/macOS flake checks.

## Reproduction

Build CLI binaries from separate baseline/current checkouts. The baseline and
current toolchains must be available before disabling remote lookups.

```sh
python3 scripts/benchmark-ci.py \
  --before /path/to/baseline-checkout --after "$PWD" \
  --source /path/to/source --runs 5 \
  --nix-option always-allow-substitutes false --nix-option substituters ''

# Keep remote caches enabled, while honoring derivation hints:
python3 scripts/benchmark-ci.py \
  --before /path/to/baseline-checkout --after "$PWD" \
  --source /path/to/source --runs 5 \
  --nix-option always-allow-substitutes false

python3 scripts/benchmark-export.py --before /tmp/drvgo-before \
  --after /tmp/drvgo-after -C /path/to/source --runs 7
# For an offline non-vendored module, also pass --module-proxy file:///path/to/proxy.
python3 scripts/benchmark-build.py --before /path/to/before-export \
  --after /path/to/after-export --runs 5
python3 scripts/benchmark-evaluation.py --before /path/to/before-export \
  --after /path/to/after-export --iets /nix/store/IETS/bin/iets --runs 7
python3 tests/iets.py --iets /nix/store/IETS/bin/iets --runs 5
```
