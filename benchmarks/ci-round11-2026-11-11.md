# Keep forwarding builders alive until process exit

Measured on Linux amd64 with Go 1.26.5 on November 11, 2026. Baseline
`8256da8626f776119e5b58db2341021236e76930`; implementation
`031622ccf7dc96ef2e8422d28f773e8d30fded1e`.
[Raw measurements and validation](ci-round11-2026-11-11.json) accompany this
reliability follow-up.

## Why change the forwarding builder

An Apple Silicon Go 1.25 compatibility job passed discovery, native empty-test
validation, archive modes and package compilation, then failed with signal 9
while running the final symlink builder. A similar failure occurred in the
preceding SDK-only planner round. The runner logs do not conclusively identify
who sent the signal.

The direct coreutils builder has a concrete problem regardless:
[`ln` closes stdout and stderr before exiting](https://github.com/NixOS/nix/issues/2176#issuecomment-394341125),
which can race Nix's EOF-triggered builder cleanup. A syscall trace of our pinned
Linux coreutils confirms `close(0)`, `close(1)`, `close(2)`, then `exit_group(0)`.
The native drvgo helper calls `os.Symlink` and leaves stdout and stderr open until
process exit; its trace confirms that neither descriptor is closed early.

Both dynamic forwarding derivations now use that helper. Errors remain fatal;
there is no retry, delay, ignored failure, or sandbox change. The planner carries
the helper's derivation context so Nix can realize its builder normally. Worker
package recipes and artifacts remain unchanged.

## Cost

Complete planner input closures copied to a local zstd level 3 cache:

| Workload | Before compressed bytes | After compressed bytes |
| --- | ---: | ---: |
| Cgo fixture | 97,357,118 | 97,467,066 |
| UPM | 290,142,836 | 290,252,784 |

Both add **109,948 compressed bytes**, **289,240 NAR bytes**, and two store paths,
including the CLI's build recipe/source metadata. This retains nearly all of the
preceding round's 26.9 MB compressed reduction. These are payload sizes, not
network download measurements.

Five alternating trials plus excluded warmups, with fresh dynamic planners and
warm tools, modules and package outputs. Strict sandboxing, IFD disabled, four
jobs/two cores; remote cache queries disabled equally on both revisions:

| Workload | Before total | After total |
| --- | ---: | ---: |
| Cgo fixture | 0.891 s | 0.895 s |
| UPM | 3.400 s | 3.448 s |

The fixture is approximately unchanged. UPM increases by 48 ms (1.4%) in this sample; this is a
reliability fix, not a speedup claim. All trials across both revisions resolve to
the exact same Go package output for each workload.

Fifteen alternating outer-helper evaluations, without builds, using iets PR #3
at `69883a64bfb0d9a95dce253dae304878e07b076e` with fallback and tracing cache off:

| Workload | Nix before → after | iets, 1 worker | iets, 4 workers |
| --- | ---: | ---: | ---: |
| Cgo fixture | 384.2 → 392.2 ms | 192.5 → 195.3 ms | 119.1 → 113.0 ms |
| UPM | 413.0 → 412.0 ms | 231.2 → 229.4 ms | 137.1 → 138.5 ms |

Each client produces the identical derivation within a revision. The timings
run sequentially after correctness tests and closure measurement finish. Exact
commands, revisions and individual samples are recorded in the JSON.

## Validation

Unit tests and vet pass. The complete local Go 1.26.5 compatibility suite passes,
including native cases, both archive modes, test binaries, cgo empty-test
validation, runtime references, and dynamic/standalone package identity.
The full iets suite passes outer/nested evaluation and builds, direct dynamic
outputs, optional tests, invalidation and runtime closures. These integration
runs overlap correctness work and their timings are not benchmark claims.

A dedicated check realizes 200 fresh, short-lived native forwarding derivations
under Nix and validates every symlink and its data. It passes locally and runs
once per platform in the default-Go compatibility job. The complete Linux
amd64/arm64 and Apple Silicon matrix remains required before merge; final status
is recorded on the PR.

Reproduce the stress check with `python3 tests/forwarding.py --count 200`.
Use the preceding round's CI, dynamic-evaluation and planner-closure commands
with this report's baseline and implementation for the cost comparison.
