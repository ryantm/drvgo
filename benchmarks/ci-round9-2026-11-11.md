# Compact compiler archives and private-edit reuse

Measured on Linux amd64 with Go 1.26.5 on November 11, 2026. Baseline
`973f1f1f82f965606a7e6b5a361063718d6e0ed5` has the same tree as merged main
`e4eea3a731573b67d2fbe5804a15339d47885bcb`. The measured implementation is
`e900adc067aa16b91ce0a041d4e59872e543f284`.
[Raw samples, closure roots and validation evidence](ci-round9-2026-11-11.json)
accompany this report.

Both new options remain **disabled by default**. `exportData = true` gives each
library an `api` output containing its compiler interface. `earlyCutoff = true`
additionally makes library outputs content-addressed. Compilation consumes API
archives; final linking still consumes full implementation archives. This is a
tradeoff for distributed workers and repeated implementation edits, rather than
a general improvement to warm CI.

## Archive transfer sizes

UPM revision `35a76c282507fb942445c0ee98427b3d1ef772bc` has 554 package units,
including 553 libraries. Complete output closures copied to a local binary
cache with zstd level 3:

| Library outputs | Closure paths | NAR bytes | Compressed bytes |
| --- | ---: | ---: | ---: |
| Full input-addressed archives | 562 | 351,613,552 | 88,546,730 |
| Compiler interfaces | 553 | 28,503,184 | 14,322,334 |

Compiler interfaces save **83.8% of compressed bytes** and **91.9% of NAR bytes**
in this comparison. All 553 interface NAR hashes match between input-addressed
and content-addressed modes. Content-addressed full archives have the same NAR
size and compress to 88,546,736 bytes.

This is not an 83.8% reduction in whole-build traffic. Final linking needs the
full archives, and a worker doing both compilation and linking can need both
sets. The benefit is smaller compiler-only inputs when work is distributed.
These are stored payload sizes, not measured network download times.

The new helper adds 12,288 NAR bytes and about 2,751 compressed bytes to compile
and link toolchain closures, with no additional dependency paths. Its changed
recipe causes a one-time package cache invalidation even with both options off.

## Private implementation edits

A 67-package fixture contains a dependency, five forwarding libraries, and a
command. Changing a non-inlined private function from returning 42 to 43 leaves
its compiler export payload unchanged. Five measured trials plus warmup, with
rotating mode order and distinct module paths per mode/trial:

| Mode | Package builds after edit | Export + evaluation + realization |
| --- | ---: | ---: |
| Full archives | 7 | 0.511 s |
| Input-addressed interfaces | 7 | 0.516 s |
| Content-addressed interfaces | 2 | 0.432 s |

Early cutoff reduces this fixture's complete edit cycle by **15.5%**. Every
result is executed and must print the changed value. The initial version is
built immediately before each edit; tool inputs and standard libraries are
warm. This is a small controlled fixture, not an application-wide rebuild
speedup claim. Edits that change inline bodies, type information, or other
exported compiler data still invalidate consumers. Not every private edit
preserves that data.

## Warm CI and graph evaluation

Five alternating UPM trials per comparison, with fresh dynamic planners and
warm tools, modules and package outputs. Strict sandboxing, IFD disabled, four
jobs and two cores; remote cache queries disabled equally for both revisions:

| After mode | Baseline total | After total | Change |
| --- | ---: | ---: | ---: |
| Default, both options off | 3.417 s | 3.406 s | Essentially unchanged |
| Input-addressed interfaces | 3.441 s | 3.468 s | +0.8% |
| Content-addressed interfaces | 3.464 s | 3.838 s | +10.8% |

The initial default warmup rebuilt the new worker's package outputs and took
43 seconds; it is excluded from the warm median. This is not a cold-build
comparison. Separate frozen-source prototype runs found about 2% and 11% warm
overhead for the two optional modes, consistent with keeping them opt-in.

Fifteen alternating evaluations per client of the already-exported UPM graph,
without builds, using iets PR #3 at
`69883a64bfb0d9a95dce253dae304878e07b076e`. Tracing cache and fallback are disabled:

| After mode | Nix before → after | iets, 1 worker | iets, 4 workers |
| --- | ---: | ---: | ---: |
| Default | 134.5 → 136.3 ms | 42.9 → 43.4 ms | 59.8 → 60.1 ms |
| Interfaces | 135.8 → 144.1 ms | 43.4 → 45.2 ms | 58.8 → 60.8 ms |
| Early cutoff | 136.7 → 110.6 ms | 42.0 → 42.7 ms | 59.5 → 59.6 ms |

Nix evaluates the content-addressed graph faster in this workload, but its
realization overhead outweighs that gain in the warm dynamic build. iets
evaluation is approximately unchanged. With the host's several remote caches
enabled, a separate all-library-output request spent many minutes on per-output
realization metadata queries. Those observations are not timed benchmark
samples; the measurements above do not model remote cache latency.

## Correctness and compatibility

The selected Go SDK's archive reader/writer extracts `__.PKGDEF` into a valid
archive. Only the implementation-derived build-ID header is removed; the export
payload, inline bodies and type information remain byte-for-byte intact.
The implementation rejects unsupported or malformed header forms.

Full local compatibility suites pass on Go 1.25.12, 1.26.5 and 1.26.6. Native
differential cases exercise both optional modes against ordinary Go, including
cgo, assembly, race, C++, external linking, workspaces, vendoring and tags.
Dedicated interface tests verify private-edit reuse, inline invalidation,
rejection of incompatible signatures, native embeds, internal/external test
binaries, race test binaries and identical standalone/dynamic outputs. They
also pass iets outer/nested evaluation and builds on all three SDKs.

Runtime store paths carried through an inline library function survive in its
API, implementation and final binary closures. Copying the API alone retains
the used data and excludes the full archive and unused data. A derivation-aware
API copy publishes its realization metadata; fetching its closure into a fresh
isolated local store retains exactly the API and its runtime data.

Modern `nix build` passes the multi-output CA probe with Nix 2.34.8 and 2.35.3.
Legacy `nix-build` 2.34.8 aborts in output-path reporting for that probe; use the
modern client for early cutoff. Normal defaults retain ordinary input-addressed
library outputs. The Linux amd64/arm64 and Apple Silicon matrix remains the
merge gate; its final status is recorded on the PR.

## Reproduction

```sh
python3 scripts/benchmark-export-data.py --drvgo ./bin/drvgo --toolchain "$tc"

python3 scripts/benchmark-ci.py --before /path/to/baseline --after . \
  --source /path/to/pinned-upm --package ./cmd/upm \
  --vendor-hash 'sha256-A4CU4C5SmEZP6Q+CVHjp+Jy4UxRXAnpvhzrsdq4NlsM=' \
  --after-export-data --after-early-cutoff --runs 5 \
  --nix-option sandbox true --nix-option sandbox-fallback false \
  --nix-option substituters '' --nix-option always-allow-substitutes false

python3 scripts/benchmark-evaluation.py --before /path/to/baseline-export \
  --after /path/to/new-export --iets /path/to/iets --runs 15 \
  --after-export-data --after-early-cutoff
```

Omit `--after-early-cutoff` for input-addressed interfaces and omit both flags
for default behavior. `tests/export-data.py` runs the correctness checks for
both modes. Its optional `--nix-option substituters ''` requires the dynamic
planner's inputs to have been fetched first; ordinary toolchain construction
alone does not provision the pinned recursive Nix executable.
