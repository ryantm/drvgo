# Parallel source preparation, November 11, 2026

Measured on Linux amd64 with Go 1.26.5. Baseline `cbf2566` has the same
production code and tree as merged main `a30504b`; implementation `1dfd680`
prepares source snapshots with up to four workers. The change preserves every
snapshot, compression limit, encoded payload, package recipe, and worker tool.
[Raw measurements and validation](ci-round15-2026-11-11.json) accompany this report.

## What the profile found

An instrumented prepared-UPM planner spent approximately 29 ms scanning source
references and 85 ms encoding small snapshots. These independent per-snapshot
operations ran sequentially. The new implementation bounds parallelism by both
four workers and `GOMAXPROCS`, with a separate scan buffer and reusable compressor
per worker. It applies results in the original source order after joining all
workers, and collects runtime references before substituting encoded payloads.

The same diagnostic recorded about 1.01 s for nested iets instantiation and
127 source additions totaling 60.3 MB of NAR data. Its evaluation profile sampled
about 91 ms of CPU time. This suggests store registration and source handling
remain a larger lead than rewriting the Nix evaluator expressions. The largest
snapshots contain required SQLite and tree-sitter C sources. This change keeps
them intact. Diagnostic timings are excluded from the comparisons below.

## Standalone exporter

Seven alternating trials plus warmups for each thread count use prepared UPM
modules, the same explicit full toolchain, and existing output replacement.
`GOMAXPROCS` controls both the exporter and its Go subprocesses. All 48 runs,
including warmups, have byte-identical `graph.json`, `evaluation.json`,
`scripts.nix`, and resolved toolchain metadata, including all source hashes.

## Complete warm CI

Seven alternating before/after trials plus warmups force a fresh planner each
time, with warm tools and compiled Go package outputs. Each total includes outer
Nix evaluation, realization, nested planning, and final output forwarding, using
`scripts/benchmark-ci.py`. Sandboxing is enabled without fallback; IFD, remote
cache queries, and forced substitutions are disabled. Nix uses four build jobs
and two cores per job. The optional nested evaluator is static iets PR #3 at
`69883a64bfb0d9a95dce253dae304878e07b076e`, one evaluator worker, with both evaluator
caches and fallback disabled. All trials preserve the same Go command output.

| Workload | Nested evaluator | Before | After | Reduction |
|---|---|---:|---:|---:|
| fixture | nix | 0.874 s | 0.846 s | 3.2% |
| fixture | iets | 0.672 s | 0.653 s | 2.9% |
| upm-proxy | nix | 3.434 s | 3.374 s | 1.8% |
| upm-proxy | iets | 3.048 s | 2.973 s | 2.5% |
| upm-prepared | nix | 2.552 s | 2.475 s | 3.0% |
| upm-prepared | iets | 2.132 s | 2.065 s | 3.2% |

UPM is revision `35a76c282507fb942445c0ee98427b3d1ef772bc`, package `./cmd/upm`.
Proxy mode uses the pinned vendor hash in `examples/upm/dynamic.nix`; prepared
mode supplies the same existing module cache to both revisions. These are warm
CI measurements, not cold compilation or network-download measurements.

Reproduce with the commands in the JSON, replacing the recorded before/after
checkout paths. For example, for prepared modules and nested iets:

```sh
python3 scripts/benchmark-ci.py --before /path/to/baseline --after /path/to/current \
  --source /path/to/upm --package ./cmd/upm --runs 7 \
  --vendor-hash sha256-A4CU4C5SmEZP6Q+CVHjp+Jy4UxRXAnpvhzrsdq4NlsM= \
  --module-cache /nix/store/your-prepared-module-cache \
  --before-iets /nix/store/your-iets --after-iets /nix/store/your-iets \
  --nix-option sandbox true --nix-option sandbox-fallback false \
  --nix-option substituters '' --nix-option always-allow-substitutes false
```

## Size and validation

Complete fixture planner inputs gain 12,336 NAR bytes and 3,619 zstd-level-3
bytes, with unchanged path counts, for either nested evaluator. Worker tools,
source snapshots, package derivations, and compiled outputs are unchanged.
Compressed sizes come from fresh local binary caches; no network timing is
inferred from them.

Unit tests, vet, and focused race checks pass. Tests cover parallel determinism,
shared-snapshot order, compression boundaries, failure before graph mutation,
reference retention, invalid store queries, and broken recursive sockets.
The full local Go 1.26.5 compatibility suite passes, including native replay,
custom build IDs, relocation, tests/race mode, runtime data, compact archives,
empty tests, strict recursive store visibility, and dynamic builds without IFD.
The full iets suite passes outer/nested evaluation, ordinary/direct builds,
public flake use, embed invalidation, optional-test errors, and runtime closures.
Linux amd64/arm64 and Apple Silicon CI remains the merge gate.
