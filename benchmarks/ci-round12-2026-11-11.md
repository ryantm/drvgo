# Optional nested iets planning

Measured on Linux amd64 with Go 1.26.5 on November 11, 2026. Baseline
`3e8a3abf112cec19216baedc7f85b715bae2c607` has the same tree as merged main
`3c2a8130c9eeeae296bb35d977203201f8927651`. Implementation:
`d30cce7fbbf250d0be6db64cf941fc4868ad202d`.
[Raw trials, commands, closures and validation](ci-round12-2026-11-11.json).

## Change

`nix/dynamic.nix` and `lib.mkGoPackage` accept an optional `iets` package.
It instantiates the generated graph through the restricted recursive store,
using iets PR #3 at `69883a64bfb0d9a95dce253dae304878e07b076e`.
The invocation uses one worker, disables tracing and Nix fallback, and maps
Nix's recursive Unix socket to `NIX_DAEMON_SOCKET_PATH`. Evaluation errors fail
the planner normally. Nix's query commands remain available for validating
runtime references and preserving toolchain metadata.

The default is `iets = null`. Its planner derivation is byte-for-byte unchanged
for all nine combinations of Linux amd64/arm64 and Apple Silicon with Go
1.25.12, 1.26.5 and 1.26.6. Neither the default inputs nor worker recipes change.
The compatibility adapter now calls the public option, and the integration
suite also exercises `lib.mkGoPackage` directly.

## CI build time

Five alternating trials plus excluded warmups, with a fresh planner each time
and warm tools, modules and Go package outputs. Both sides use Nix for outer
evaluation, strict sandboxing, IFD disabled, four jobs/two cores, and disabled
remote cache lookups. All tests and closure copies finish before timing begins.
The optional planner uses upstream's static Linux iets package.

| Workload | Default Nix planner | Nested iets | Change |
| --- | ---: | ---: | ---: |
| Cgo fixture | 0.877 s | 0.872 s | approximately unchanged |
| UPM, module proxy | 3.480 s | 3.130 s | 10.1% faster |
| UPM, prepared module cache | 2.534 s | 2.225 s | 12.2% faster |

Every before/after trial resolves to the identical Go package output for its
workload. These measurements cover outer evaluation, planning and forwarding;
they do not measure cold compilation or network downloads. Prepared modules
are the same existing cache on both sides, so extraction costs do not account
for that comparison's improvement.

Fifteen alternating outer-helper evaluations, excluding builds, produce these
medians. The iets clients use the same static package as the nested planner,
with tracing and fallback disabled:

| Workload | Nix before → after | iets, 1 worker | iets, 4 workers |
| --- | ---: | ---: | ---: |
| Cgo fixture | 389.4 → 384.9 ms | 245.6 → 243.6 ms | 126.7 → 128.9 ms |
| UPM, module proxy | 406.9 → 411.1 ms | 274.2 → 273.7 ms | 134.2 → 130.9 ms |
| UPM, prepared modules | 405.2 → 403.0 ms | 273.5 → 272.5 ms | 135.1 → 134.4 ms |

Each evaluator produces the same derivation for a given configuration. Outer
evaluation is approximately unchanged; the benefit comes during planning.

## Input size

Actual complete planner input closures, including raw recipe metadata, copied
to a local zstd level 3 binary cache:

| Workload | Default compressed bytes | Nested static iets |
| --- | ---: | ---: |
| Cgo fixture | 97,467,066 | 102,597,609 |
| UPM, prepared modules | 251,486,086 | 256,616,629 |

Both add one store path, **14,449,896 NAR bytes** and **5,130,543 compressed
bytes**. This is an optional tradeoff for faster planning. The default has no
additional closure cost. These are payload sizes, not network timings.

The original iets package at this pin adds substantially more data. Separately
measured evaluator closures are:

| iets package | Paths | NAR bytes | Compressed bytes |
| --- | ---: | ---: | ---: |
| Default dynamic build | 32 | 175,337,640 | 59,686,867 |
| Dynamic, `fallbackGit = false` | 7 | 63,477,512 | 19,663,269 |
| Upstream static Linux build | 1 | 14,449,896 | 5,130,543 |

Both lean variants pass the full drvgo iets integration suite. The static
package has no runtime dependencies. Publishing its output to a binary cache
avoids compiling iets itself on cold CI machines. This round validates nested
iets on x86_64-linux; other platforms retain the tested default Nix planner.

## Validation and reproduction

Full static and no-Git integration runs pass outer/nested evaluation, dynamic
builds, warm reuse, direct `outputOf`, embedded-file invalidation, optional pure
and cgo tests, and runtime-reference closure checks. Invalid Go or C code still
fails after an empty-test output has been cached. Public flake-helper builds
preserve package identity with both evaluators. Additional static checks cover
both optional compiler-archive modes, including content-addressed packages.
Integration-run timings are not used in the performance tables.

The complete existing Linux amd64/arm64 and Apple Silicon matrix remains
required before merge; its final status is recorded on the PR.

```sh
iets=$(nix build github:replit/iets/69883a64bfb0d9a95dce253dae304878e07b076e#static \
  --no-link --print-out-paths)
python3 tests/iets.py --iets "$iets/bin/iets" --runs 1
python3 scripts/benchmark-ci.py --before /path/to/baseline --after . \
  --source /path/to/upm --package ./cmd/upm \
  --module-cache /nix/store/...-drvgo-module-cache --after-iets "$iets" \
  --runs 5 --nix-option sandbox true --nix-option sandbox-fallback false \
  --nix-option substituters '' --nix-option always-allow-substitutes false
python3 scripts/benchmark-evaluation.py --before /path/to/baseline --after . \
  --dynamic-source /path/to/upm --package ./cmd/upm \
  --module-cache /nix/store/...-drvgo-module-cache --after-iets "$iets" \
  --iets "$iets/bin/iets" --runs 15
```

For module-proxy trials, replace `--module-cache` with `--vendor-hash` on both
benchmark commands. For the fixture, use `tests/fixture`, package `.`, and
neither dependency option. The JSON records the exact pinned source, proxy
hash, cache output and individual commands used here.
