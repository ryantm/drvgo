# Smaller native dependency archives, November 12, 2026

When the final Go link discards DWARF, drvgo now also disables ordinary native
compiler debug data. The previous round omitted Go compiler DWARF but still
compiled C and C++ objects with `-g`. This is particularly expensive for UPM's
SQLite and tree-sitter dependencies.

Only the supported GCC/Clang driver commands ending in cmd/go's `-c source`
shape receive a final `-g0` before that suffix. The Go cgo invocation, its DWARF
probes for discovering C types, compiler capability probes and native linker
commands retain their original arguments. Default/debug-preserving links and
experimental SDK adapters keep their existing recipes. This extends the
existing root-linker flag handling, including `-s`, `-w`, repeated boolean flags,
and `-s -w=false`.

Response files, option terminators, unknown compiler drivers, and custom or
unknown `-g` options keep their original commands. A GCC 15.3.0 probe showed why
this matters: `-g -gbtf -g0` removes explicitly requested BTF too, while
`-g -gctf -g0` retains CTF and DWARF. BTF, CTF, split DWARF and CodeView must not
be treated as ordinary DWARF. The raw report includes these six actual compiler
commands and their object sections. The flag's ordinary behavior is documented
by [GCC](https://gcc.gnu.org/onlinedocs/gcc/Debugging-Options.html) and
[Clang](https://clang.llvm.org/docs/ClangCommandLineReference.html#debug-information-generation).

Baseline is `c67dd40`; implementation is `02a96ee`. Both include the prior Go
compiler DWARF optimization. [Raw measurements and validation](ci-round25-2026-11-12.json)
accompany this report.

## Dependency rebuilding and cache payloads

Both workloads use `-s -w -buildid=drvgo-probe`, Go 1.26.5 and the same full
native toolchain. Each trial recompiles every package using `nix-build --check`,
with warm tools, sources and dependency outputs. The fixture uses five
alternating pairs plus warmups; UPM uses three pairs plus warmups. Strict
sandboxing is enabled without fallback, IFD and substitutions are disabled,
and Nix uses four jobs/two cores. No other local builds run during timing.

| Workload | Packages | Before | After | Change |
|---|---:|---:|---:|---:|
| fixture | 67 | 3.734 s | 3.780 s | +1.2% |
| UPM | 554 | 45.211 s | 37.653 s | -16.7% |

UPM saves about **7.6 seconds (16.7%)**. The small fixture is effectively flat,
with a measured 46 ms increase; this is a native-heavy workload improvement,
not a general speedup for every Go application. The changed scripts affect
three native packages/22 compiler commands in the fixture and nine native
packages/78 commands in UPM.

| Workload | Package NAR before | Package NAR after | Package zstd before | Package zstd after |
|---|---:|---:|---:|---:|
| fixture | 26,118,816 | 26,044,944 | 6,851,020 | 6,820,092 |
| UPM | 260,626,784 | 253,469,840 | 69,879,582 | 66,857,463 |

UPM package outputs lose **3,022,119 compressed bytes (4.3%)**. Their complete
closure shrinks from 87,079,559 to 81,486,013 compressed bytes, a saving of
**5,593,546 bytes (6.4%)**, including two source snapshots no longer retained
by the package outputs. The fixture saves 30,928 compressed package bytes and
64,768 bytes across the complete closure. These are payload sizes from a fresh
local zstd-level-3 binary cache, excluding metadata/protocol overhead; they are
not network-transfer timings.

The final guarded implementation matches every exported prototype file:
732 for the fixture and 3,167 for UPM. The two selected applications retain
byte-identical final executables with the explicit build ID above, and both
run successfully. This does not promise unchanged automatic build IDs or
identical output bytes for arbitrary native programs. Stripped native package
recipes and their dependents change, causing a one-time cache miss. Debug and
stripped native builds use separate archives. Compiler and runtime settings
beyond the omitted debug data are unchanged.

## Complete cached CI

Seven alternating pairs plus warmups cover both workloads, debug/stripped flags
and Nix/iets nested planners: 128 builds in total. Every default build preserves
its baseline package output. Each stripped variant is stable across its own
trials; its before/after derivation paths differ, as expected. With the explicit
build ID, both final executables have identical bytes for each workload. All
selected executables run successfully.

| debug | fixture | nix | 0.873 s | 0.870 s | -0.4% |
| debug | fixture | iets | 0.663 s | 0.664 s | +0.2% |

Cached CI differences range from -2.2% to +1.6%, with mixed changes across

Each run forces fresh dynamic planning with warm tools and package outputs.
The outer client is Nix; nested iets is static upstream PR #3 at
`69883a64bfb0d9a95dce253dae304878e07b076e`, one worker, caches disabled and fallback
forbidden. Sandboxing is required without fallback, IFD/substitutions are off,

`35a76c282507fb942445c0ee98427b3d1ef772bc`, package `./cmd/upm`, with the same
prepared module cache. The raw results separate outer evaluation and realization.

## CLI bootstrap and planner payload

Five alternating pairs plus warmups force twelve fresh CLI package builds with
fresh Go caches and warm SDK/filesystem caches, including all unit tests and
vet. The same strict sandbox and no-IFD/no-substitution settings apply.

Median evaluation plus realization is **6.260 s before and 6.264 s after**
(+0.1%). Each revision has stable installed output bytes across all six
builds and retains the same tzdata runtime reference.

| Evaluator | Paths, unchanged | Before NAR bytes | After NAR bytes | Before zstd bytes | After zstd bytes |
|---|---:|---:|---:|---:|---:|
| nix | 958 | 324,527,528 | 324,538,936 | 93,736,347 | 93,739,389 |
| iets | 900 | 210,370,192 | 210,381,600 | 54,827,056 | 54,830,098 |

Planner inputs add **11,408 NAR bytes and 3,042 compressed bytes**. The installed
CLI grows from 3,391,312 to 3,395,408 bytes (+4,096); its binary bytes change.

Complete input closures include raw derivation metadata. Compiler, linker,
native and full worker toolchains are identical. Payload measurements use fresh
local zstd-level-3 binary caches and exclude network-transfer latency.

## Validation

Unit tests and vet pass. A new archive-level integration test checks native
ELF/Mach-O object DWARF for default, stripped and `-s -w=false` builds, exercises
cgo structs and enum constants, runs the result, and checks a custom build ID.
It passes locally with Go 1.25.12, 1.26.5 and 1.26.6. Argument-selection tests
preserve cgo discovery, probes, native links, response files and custom debug
formats, and retain experimental-SDK behavior.

The full Go 1.26.5 compatibility suite passes fourteen differential cases and
all three archive layouts, including stripped C++ exceptions, race-enabled cgo,
native assembly, external linking, runtime store references, optional-test
validation, source edits and previous-plan reuse. The new archive integration
is required by the compatibility harness, and stripped C++ also runs through
the public dynamic helper with IFD disabled.

The full iets PR #3 suite passes outer/nested/direct builds, debug and stripped
modes, embed invalidation, empty and native test validation, runtime inputs and
previous-plan reuse. Linux x86-64, Linux ARM64 and macOS ARM64 across all three
supported SDKs remain the merge gate.

## Reproduction

Export the same source, package, module cache and full toolchain with each
revision, passing `-ldflags '-s -w -buildid=drvgo-probe'`. The raw report records
the complete fixture and UPM export commands and every timed trial. Rebuild
all exported packages using:

```sh
python3 scripts/benchmark-build.py --before /path/to/before-export \
  --after /path/to/after-export --runs 3 --out /path/to/new-results
```

For complete cached CI, use `scripts/benchmark-ci.py` with both checkouts and
`--ldflags='-s -w -buildid=drvgo-probe'`; add the same `--before-iets` and
`--after-iets` package for nested iets. Exact commands, Nix settings, store
roots, binary hashes and closure payloads are included in the JSON.
