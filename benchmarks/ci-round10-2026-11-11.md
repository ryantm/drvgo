# Compact Go discovery inputs

Measured on Linux amd64 with Go 1.26.5 on November 11, 2026. Baseline
`845a46abd776d163fcecf0655038e5358775f172` has the same tree as merged main
`6d0012de91771b7f5a2a0c19231e8477e6b78f06`. The measured implementation is
`8d1d1258e63baa775655a40555cb350a4c6cdb81`.
[Raw samples, input roots and validation evidence](ci-round10-2026-11-11.json)
accompany this report.

Normal dynamic discovery now uses a compact bundle containing the original Go
driver, complete SDK source and library data, and exact tool-version responses
captured from the selected SDK. The metadata entry points reuse drvgo and reject
actual compilation requests. Workers continue using the same compiler and linker
bundles, preserving their package derivations and cached outputs.

## Planner transfer sizes

Complete planner input closures, including application source, module proxy and
raw derivation metadata, copied to a local binary cache using zstd level 3:

| Workload | Measurement | Before | After |
| --- | --- | ---: | ---: |
| 67-package cgo fixture | Compressed bytes | 124,271,680 | 97,357,118 |
| | NAR bytes | 418,888,488 | 338,909,712 |
| | Store paths, including recipes | 962 | 962 |
| 554-package UPM | Compressed bytes | 317,057,398 | 290,142,836 |
| | NAR bytes | 653,102,168 | 573,123,392 |
| | Store paths, including recipes | 963 | 963 |

Both save **26.9 MB compressed** and **80.0 MB of NAR data**. That is **21.7%**
of the fixture's compressed planner inputs and **8.5%** of UPM's. UPM uses
revision `35a76c282507fb942445c0ee98427b3d1ef772bc` and the same fixed module proxy
on both sides. These are stored transfer payload sizes, not network timings.

The compact bundle's own output shrinks from the SDK's 227.3 MB NAR / 61.9 MB
compressed to 147.4 MB NAR / 35.0 MB compressed. It references drvgo, which the
planner already needs. The CLI grows by 80 NAR bytes and adds no dependency
paths. Complete planner closures above account for this shared dependency once.
Worker tools and package archives are unchanged.

Constructing the bundle initially requires the full SDK and additional store
space. Publish `my-package.planningToolchain` to the binary cache for fresh CI
workers to download it directly. This is not a reduction in first-time
bootstrapping work when that output is absent from the cache.

## Warm CI and evaluation

Five alternating trials plus an excluded warmup per workload. Each build uses a
fresh dynamic planner; tools, module proxy and package outputs are warm. The
benchmark runs alone, with strict sandboxing, IFD disabled, four jobs and two
cores. Remote cache queries are disabled equally on both revisions.

| Workload | Evaluation + realization before | After |
| --- | ---: | ---: |
| Cgo fixture | 0.893 s | 0.902 s |
| UPM | 3.454 s | 3.467 s |

These small differences do not establish a warm-CI speedup or a substantial
regression. All before/after trials resolve to the exact same package output
for each workload. UPM's binary also executes successfully with `--version`.

Fifteen alternating evaluations per client of the outer dynamic helper, without
running its planner or building packages. iets PR #3 is pinned to
`69883a64bfb0d9a95dce253dae304878e07b076e`; fallback and tracing cache are disabled.
All three clients must produce the same derivation within each revision.

| Workload | Nix before → after | iets, 1 worker | iets, 4 workers |
| --- | ---: | ---: | ---: |
| Cgo fixture | 385.9 → 391.3 ms | 193.9 → 194.0 ms | 117.4 → 115.0 ms |
| UPM | 400.6 → 408.4 ms | 222.1 → 221.9 ms | 113.2 → 111.4 ms |

Nix's outer evaluation increases by about 1–2%; iets remains approximately
unchanged. These measure the dynamic helper, including toolchain evaluation,
and are not directly comparable to earlier standalone exported-graph timings.

## Native empty-test validation

`allowEmptyTests` actually compiles packages to distinguish a valid package with
no tests from broken code. A baseline reproduction found that a valid cgo
package without tests failed because SDK-only planning had no C compiler.
The validation path now retains the full native toolchain, or the full Go SDK
when `cgoEnabled = false` is explicit. The smaller discovery bundle is used only
where compilation is not required.

This restores correct behavior and deliberately retains larger inputs for that
semantic validation path. The transfer reductions above describe normal
discovery, not `allowEmptyTests` builds.

## Validation

Unit tests and vet pass. Full local compatibility suites pass on Go 1.25.12,
1.26.5 and 1.26.6, covering cgo, assembly, C++, external linking, native objects,
race and test binaries, custom build IDs, modules, runtime references, and
standalone/dynamic output identity. After restoring native empty-test inputs,
focused tests pass on all three SDKs for type errors, excluded directories,
valid cgo packages without tests, and C compilation errors.

For every supported SDK, the compact bundle preserves exact NAR hashes of
`src`, `lib`, `pkg/include`, `bin/go`, `go.env` and `VERSION`; the full SDK is
absent from its runtime closure. All six tool-version responses match, other
invocations are rejected, and all fixture package recipes match those exported
with the full toolchain. Go 1.26 also requires the vet entry to exist during
`go test -vet=off -n`, even though it does not execute vet.

The full iets suite passes outer and nested planning, direct `outputOf` builds,
embed invalidation, pure and cgo optional tests, and runtime-reference closure
checks. A C error introduced after caching an empty result fails through both
iets and Nix, with both nested evaluators. The separate interface-archive suite
passes both opt-in modes with iets on Go 1.26.5. Those options remain disabled by
default. The Linux amd64/arm64 and Apple Silicon matrix remains the merge gate;
its final status is recorded on the PR.

## Reproduction

```sh
python3 scripts/benchmark-ci.py --before /path/to/baseline --after . \
  --source /path/to/pinned-upm --package ./cmd/upm \
  --vendor-hash 'sha256-A4CU4C5SmEZP6Q+CVHjp+Jy4UxRXAnpvhzrsdq4NlsM=' \
  --runs 5 --nix-option sandbox true --nix-option sandbox-fallback false \
  --nix-option substituters '' --nix-option always-allow-substitutes false

python3 scripts/benchmark-evaluation.py --before /path/to/baseline --after . \
  --dynamic-source /path/to/pinned-upm --package ./cmd/upm \
  --vendor-hash 'sha256-A4CU4C5SmEZP6Q+CVHjp+Jy4UxRXAnpvhzrsdq4NlsM=' \
  --iets /path/to/iets --runs 15

python3 tests/iets.py --iets /path/to/iets --runs 15
```

The timing commands require tool and module inputs to be provisioned first.
For transfer sizes, instantiate each revision's `.planner.drvPath` and pass
those paths to `scripts/benchmark-planner-closure.py`. Closure roots and exact
benchmark command arguments are preserved in the accompanying JSON.
