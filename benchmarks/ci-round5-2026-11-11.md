# Compressed source snapshots, November 11, 2026

Baseline `aef482c`; implementation `48964c5`. Measurements use Linux amd64,
an Intel i7-1280P, Go 1.26.5, Determinate Nix 3.24.1 / Nix 2.35.3, and the
pinned Nix 2.34.8 inside recursive planning.
[Raw measurements and validation](ci-round5-2026-11-11.json) accompany this report.

## Fresh CI planning

Five alternating before/after trials exclude warmups. Each trial forces a fresh
planner and Go cache, with tools and compiled package outputs already available.
Remote cache queries and IFD are disabled. Sandboxing is enabled with fallback
disabled. Totals include outer evaluation, recursive planning, and forwarding
the cached command output; these are not cold compilation or network timings.

| Workload | Before median | After median |
|---|---:|---:|
| UPM, 554 package units | 3.782 s | 3.449 s |
| Synthetic command, 1,061 units | 2.469 s | 2.420 s |
| Rebuild all 62 assembly-fixture units | 3.724 s | 3.724 s |

UPM improves by **8.8%**. Its realization phase falls from 3.374 to 3.025 seconds;
outer evaluation is roughly unchanged. The synthetic difference is small, about
49 ms (2%). That graph already inlines most sources under the old 4 KiB limit.
The full fixture rebuild remains flat. Rebuilds use `nix-build --check
--max-jobs 4 --cores 2`, checking reproducibility as well as recompilation.

UPM uses revision `35a76c282507fb942445c0ee98427b3d1ef772bc`, package
`./cmd/upm`, and the pinned module proxy hash from `examples/upm/dynamic.nix`.
The synthetic workload is the 1,000 small packages plus standard library described
in the first November 11 report.

## Size tradeoff

| UPM snapshot policy | Graph store objects | Graph NAR | Graph zstd |
|---|---:|---:|---:|
| Original 4 KiB raw | 1,853 | 118.59 MiB | 27.45 MiB |
| Experimental 16 KiB raw | 1,705 | 118.94 MiB | 27.70 MiB |
| Experimental 64 KiB raw | 1,551 | 120.41 MiB | 28.48 MiB |
| Bounded compression | 1,580 | 115.86 MiB | 27.75 MiB |

These are complete generated derivation/source closures, including common
toolchain build recipes, but excluding realized tools and compiled package
outputs. Sizes sum payloads copied to a fresh local zstd level 3 binary cache;
they are not network timings or complete cold-CI download sizes.

Compression removes **273 store objects** and 2.73 MiB of uncompressed graph
data. Its compressed graph is **0.29 MiB larger (1.1%)** than the original, and
0.74 MiB smaller than simply raising the raw limit to 64 KiB. In a separate paired
comparison, it is 4.3% faster than the 16 KiB raw candidate while adding only
44 KiB of compressed graph data.

The worker executable remains 2,625,698 bytes: Go's build-ID implementation
already brings in zlib decoding. Its complete compile-toolchain NAR size is
unchanged, with about 2 KiB added to the compressed payload. The drvgo CLI closure
grows by 69,904 NAR bytes and 31,555 compressed bytes to provide the encoder.

## How it works

Snapshots up to 4 KiB keep the existing raw encoding. Larger snapshots are
eligible up to 64 KiB decoded, including filename and metadata costs. Each file
uses zlib only when it is smaller than the original. The combined payload,
filenames, and metadata must fit a 16 KiB budget before base64 encoding; otherwise
the entire snapshot stays a separate store object. No partial snapshot is inlined.

The exporter reuses one fast compressor across files and snapshots. The native
worker checks the declared decoded length and stream checksum before publishing
each file, preserving exact bytes and executable modes. Runtime store references
are collected before compression.

A compression-only probe over the eligible UPM snapshots measured approximately
65 ms at level 1, 89 ms at level 3, and 125 ms at level 6. The stronger levels fit
only seven and ten additional snapshots, respectively. These are in-memory
encoding measurements, not full CI trials; the implementation retains level 1.

## Evaluation and validation

Five alternating trials evaluate already-exported UPM graphs with IFD, iets
tracing caches, and classic fallback disabled. The compiled-file cache is warm.
All evaluators agree on the derivation path for each graph.

| Evaluator | Before | After |
|---|---:|---:|
| Nix | 133 ms | 133 ms |
| iets, 1 worker | 42 ms | 42 ms |
| iets, 4 workers | 57 ms | 59 ms |

Standalone evaluation remains essentially flat. The planning improvement comes
from reducing recursive store registration work, not a faster Nix expression.
replit/iets PR 3 at `69883a64bfb0d9a95dce253dae304878e07b076e` also passes outer
and nested dynamic builds, direct output builds, repeat builds, embed invalidation,
optional tests, and runtime-reference cases.

Unit tests and vet pass. The full Go 1.26.5 compatibility suite passes, including
compressed/raw/separate-source transitions and retained runtime references.
All three supported Go toolchains build; a compressed cgo-header fixture builds
after removing its original sources and reproduces its output with `--check`
under Go 1.25.12, 1.26.5, and 1.26.6. This test is required by the CI matrix.
Linux arm64 and Apple Silicon validation is pending that matrix.

With the same discovery toolchain and module-cache directory, all **554 UPM
outputs are byte-identical** between compressed and raw 64 KiB snapshots.
UPM also passes `--version` and `list-languages` smoke tests. Migrating from the
original policy changes worker and package recipes, including generated Go build
IDs and some native debug paths, so existing outputs need a one-time rebuild.
Debug information and custom build IDs remain supported.

A separate baseline limitation surfaced during validation: UPM's external
`go-sqlite3` module produces different automatic Go build IDs in ordinary and
dynamic discovery, despite otherwise identical replay commands. The discrepancy
predates compression; the fixtures used for ordinary/dynamic cache-sharing tests
continue to pass. Module-cache path normalization is a follow-up investigation.
