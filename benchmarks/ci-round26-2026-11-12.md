# Smaller native worker toolchains, November 12, 2026

The native toolchain still explicitly bundled Bash, coreutils, sed, findutils
and pkg-config after replay moved to the native runner. Replay implements its
file operations itself, and pkg-config dependency injection is unsupported.
Remove those direct entries from the native bundle. The pinned compiler
wrappers retain their own shell and utility dependencies through their store
references; GCC/Clang, C++, binutils, SDK inputs and Darwin's explicit dsymutil
entry remain available.

The archive stress test previously used the toolchain's Bash solely to set its
child's descriptor limit. It now uses the test host's POSIX shell for that setup,
and fails if setting the limit fails. Its 96 archive actions, second archive,
reference-Go byte comparison and 64-descriptor limit remain intact. The initial
compatibility run exposed this harness dependency; the corrected test and full
suite subsequently passed.

Baseline is `1156b2d`; the implementation comprises `8092045` and `8ea3823`.
[Raw measurements and validation](ci-round26-2026-11-12.json) accompany this report.

## Worker payload

Complete closures copied to a fresh local zstd-level-3 binary cache on Linux
x86-64 with Go 1.26.5:

| Bundle | Paths before / after | NAR before | NAR after | zstd before | zstd after |
|---|---:|---:|---:|---:|---:|
| compile | 4 / 4 | 35,594,152 | 35,594,152 | 11,522,096 | 11,522,096 |
| link | 9 / 9 | 80,002,312 | 80,002,312 | 25,338,285 | 25,338,285 |
| native | 42 / 33 | 450,226,496 | 434,799,512 | 141,177,828 | 137,619,958 |
| full SDK/native bundle | 48 / 39 | 682,115,584 | 666,598,520 | 203,495,063 | 199,933,925 |

The native closure saves **3,557,870 compressed bytes (2.5%)**, or 15,426,984 NAR
bytes, and nine store paths. The full SDK/native bundle saves 3,561,138
compressed bytes. That full bundle is distinct from the compact toolchain used
for dynamic planning, measured below. These are payload sizes, excluding
metadata/protocol overhead, with no network-transfer timing claim.

The removed closure paths include interactive Bash, ncurses, readline,
findutils, sed, pkg-config and its wrapper, plus two utility support paths.
The compiler's noninteractive Bash, coreutils and grep dependencies remain.
The pure Go compile and link bundles are identical store paths, and compiler,
linker, archive-helper and Go executables retain their exact existing targets.

## Package identity and behavior

Exported unit scripts and source hashes match their baselines for the pure Go
assembly fixture, the cgo fixture and UPM. The 62-package pure Go build retains
all package derivations and its final output. Updating the native bundle changes
four of 67 fixture packages and 164 of 554 UPM packages, including dependents;
these receive a one-time cache miss. The other packages keep their cache keys.

The cgo fixture and UPM use `-s -w -buildid=drvgo-probe` for this artifact
comparison. Both retain byte-identical final executables and run successfully.
Automatic build IDs can change with the toolchain path, so this is not a general
promise of unchanged native binary bytes. A separate actual export probe
confirms the same explicit unsupported-pkg-config diagnostic before and after.

## Cached dynamic CI

Seven alternating pairs plus warmups cover debug and stripped builds of the cgo
fixture and UPM, using Nix and iets nested planners: 128 builds total. Package
outputs remain stable within each revision and change between revisions as
expected for these native workloads. Every selected executable runs successfully;
the stripped variants with explicit build IDs also retain identical bytes.

| Mode | Workload | Nested evaluator | Before | After | Change |
|---|---|---|---:|---:|---:|
| debug | fixture | nix | 0.849 s | 0.851 s | +0.2% |
| debug | fixture | iets | 0.671 s | 0.653 s | -2.6% |
| debug | upm-prepared | nix | 2.504 s | 2.462 s | -1.7% |
| debug | upm-prepared | iets | 2.057 s | 2.037 s | -0.9% |
| stripped | fixture | nix | 0.866 s | 0.872 s | +0.6% |
| stripped | fixture | iets | 0.664 s | 0.651 s | -2.0% |
| stripped | upm-prepared | nix | 2.478 s | 2.507 s | +1.1% |
| stripped | upm-prepared | iets | 2.064 s | 2.060 s | -0.2% |

Differences range from -2.6% to +1.1%, with mixed changes across individual
phases. Treat cached CI and evaluation time as effectively unchanged. Warmup
trials populate newly keyed native outputs and are excluded from the medians.

Each run forces fresh planning with warm tool and package caches. The outer
client is Nix; nested iets is static upstream PR #3 at
`69883a64bfb0d9a95dce253dae304878e07b076e`, one worker, caches disabled and fallback
forbidden. Sandboxing is required without fallback, IFD/substitutions are off,
and Nix uses four jobs/two cores. UPM is revision
`35a76c282507fb942445c0ee98427b3d1ef772bc`, package `./cmd/upm`, with the same
prepared module cache. Stripped builds use `-s -w -buildid=drvgo-probe`.

## Planner payload and CLI bootstrap

| Evaluator | Paths before / after | NAR before | NAR after | zstd before | zstd after |
|---|---:|---:|---:|---:|---:|
| nix | 958 / 929 | 324,538,936 | 324,434,264 | 93,739,389 | 93,696,694 |
| iets | 900 / 871 | 210,381,600 | 210,276,928 | 54,830,098 | 54,787,403 |

Complete planner input closures lose **29 paths, 104,672 NAR bytes and 42,695
compressed bytes**, including raw derivation metadata. Pure Go compiler/linker
recipes stay identical; native and full-toolchain recipes change. The installed
CLI remains 3,395,408 bytes, though its embedded template and binary bytes change.

Five alternating pairs plus warmups force twelve fresh CLI package builds with
fresh Go caches and warm SDK/filesystem caches, including all unit tests and
vet. They use strict sandboxing, IFD/substitutions disabled, four jobs/two cores.
Median evaluation plus realization is **6.258 s before and 6.269 s after**
(+0.2%), effectively flat. Each revision has stable installed output bytes
across six builds and retains the same tzdata runtime reference.

## Validation and reproduction

Unit tests, vet and integration vet pass. The full Go 1.26.5 compatibility suite
passes fourteen differential cases in all three archive layouts, native archive
DWARF checks, C++ exception handling, race/cgo, assembly and external linking,
runtime references, custom build IDs, tests, previous-plan reuse, and source
invalidation. The full iets PR #3 suite passes outer/nested/direct builds,
stripped/debug-preserving links, runtime inputs, optional/native-test validation,
embed invalidation and prior-plan reuse. Linux x86-64/ARM64 and Apple Silicon
macOS across all three supported SDKs remain the merge gate.

recipe for actual dynamic inputs. `scripts/benchmark-ci.py` and
