# Native dynamic planner orchestration, November 11, 2026

The dynamic planner now uses drvgo to create its home directory, run the exporter,
write the nested Nix expression, invoke the selected evaluator, and copy the
resulting derivation. These steps previously required an interactive Bash build
and coreutils. Nix or iets still performs evaluation and registration.

Baseline `cdce8ab` includes the bootstrap test-cache improvement; implementation
`ed4ed06` replaces the shell wrapper and keeps the evaluator executable in its
own derivation attribute. A subsequent commit adds only documentation and results.
[Raw measurements and validation](ci-round20-2026-11-11.json) accompany this report.

## Planner input closures

| Evaluator | Paths | Before NAR bytes | After NAR bytes | Before zstd bytes | After zstd bytes |
|---|---:|---:|---:|---:|---:|
| nix | 964 → 958 | 339,232,608 | 324,784,568 | 97,478,978 | 93,794,338 |
| iets | 909 → 900 | 235,728,016 | 210,627,232 | 61,776,723 | 54,885,047 |

This saves **3.68 MB compressed (3.8%) with Nix**, and **6.89 MB (11.2%) with iets**.
The NAR reductions are 14.45 MB and 25.10 MB, respectively. Measurements include
raw derivation metadata and use a fresh local binary cache with zstd level 3.
They measure payload size, not network-transfer time or remote-cache compression.

The interactive shell, readline, ncurses, coreutils, GMP and attr outputs disappear
from both measured input closures. With static iets, the ACL and GCC runtime
outputs also become unnecessary. The Go discovery bundle still has its own
transitive dependencies, including non-interactive Bash. This change removes the
planner's explicit shell/coreutils requirements, not every shell in the SDK.

Compiler, linker, native and full worker-toolchain derivation paths remain
identical. The CLI and compact planning bundle have new paths because the CLI
implementation changed. No new public option or dependency-cache artifact is
introduced.

## Complete warm CI

Seven alternating trials plus one warmup per revision cover the fixture and UPM
with a module proxy, prepared modules, and prepared modules plus a previous plan.
Each invocation forces a fresh planner; the CLI, toolchains and compiled package
outputs are warm. Totals include outer Nix evaluation, planning, registration,
and forwarding. Sandboxing is enabled without fallback; IFD, substituters and
forced substitutions are disabled. Nix uses four jobs and two cores per job.

Nested iets is the static build of upstream PR #3 at
`69883a64bfb0d9a95dce253dae304878e07b076e`, with one worker and both caches and
fallback disabled. All 128 runs produce the same package output as their baseline.

## CLI bootstrap and evaluator layout

Five alternating bootstrap trials plus warmups force twelve fresh CLI package
builds, including unit tests and vet, with empty per-build Go caches. The SDK and
filesystem caches are warm and substitutions are disabled. The median changes
from **6.437 s to 6.463 s (+0.4%)**. The existing bootstrap improvement is preserved.
CLI executable bytes change as expected; each revision's installed NAR is stable
across its six runs, and runtime references remain identical.

An initial wrapper placed the evaluator path first in its argument list. With
this host's parallel Determinate Nix evaluator, UPM outer evaluation increased by
about 0.1 s. Evaluation-only comparisons isolated the layout: moving the evaluator
path into a separate derivation attribute removed that regression, while serial
evaluation was effectively unchanged. Explicit string coercion and selecting the
same binary output through `getBin` did not help. The final implementation and
all reported CI measurements use the separate attribute. Diagnostic variants,
statistics and raw timings are retained in the JSON; they are not extra supported
planner configurations. No machine or evaluator settings were changed.

## Validation

The native driver keeps stdout and stderr open until exit, preserving the earlier
builder cleanup-race fix. The exporter remains a child process so its heap is
released before the evaluator starts. Arguments are passed directly, preserving
spaces, quotes and literal shell syntax. Subprocess failures and malformed
returned paths fail the build. Nested iets still requires the recursive Unix
socket and disables fallback; macOS reads newly registered derivations through
the same restricted daemon operation used by the previous wrapper.

Unit tests and vet pass, including direct subprocess tests for quoting,
environment selection, export/evaluator failures, malformed output and invalid
store transport. The full Go 1.26.5 compatibility suite passes all ten differential
cases plus dynamic, race, native-object, custom-build-ID, runtime-reference,
module-cache, incremental and optional-test validation. The full iets suite passes
outer/nested evaluation, direct `outputOf` builds, the public flake helper, native
empty-test validation, runtime references and previous-plan invalidation.

These local checks ran on x86-64 Linux. The Linux x86-64/ARM64 and Apple Silicon
macOS SDK matrix remains a separate merge gate. Sandboxing, recursive store
visibility and error validation are preserved.
