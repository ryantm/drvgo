# Native archive handling, November 11, 2026

Baseline `66d6554`; implementation `970d5a6`. Measurements use Linux amd64,
an Intel i7-1280P, Go 1.26.5, and Determinate Nix 3.24.1 / Nix 2.35.3.
[Raw samples, store paths, and validation](ci-round4-2026-11-11.json) accompany
this report. Each timing comparison alternates before/after order, with five
measured trials after a warmup. Remote queries and IFD are disabled; Nix builds
use sandboxing with fallback disabled.

## Size and time

| Workload | Before median | After median | Change |
|---|---:|---:|---:|
| Replay one archive append, including worker startup | 2.497 ms | 1.482 ms | 40.7% faster |
| Rebuild helpers with a fresh Go cache | 2.818 s | 2.575 s | 8.6% faster |
| Rebuild all 62 assembly-fixture package units | 3.715 s | 3.703 s | 0.3% faster |

The full package rebuild is essentially unchanged. The focused archive benchmark
runs 100 workers per trial with already compiled inputs. It includes archive
copying and output publication, but excludes compilation, Nix scheduling, and
network transfer. Helper rebuilds use `nix-build --check --max-jobs 1 --cores 2`;
package rebuilds request every unit with `--check --max-jobs 4 --cores 2`.
All rebuilds reproduce the existing outputs, including the helper built through
a temporary source overlay.

|---|---:|---:|---:|---:|
| Compile/assembly | 35.82 MiB | 33.92 MiB | 11.84 MiB | 10.98 MiB |
| Pure Go link | 78.17 MiB | 76.27 MiB | 25.02 MiB | 24.15 MiB |

The compressed compile-toolchain closure is **7.3% smaller**. Sizes sum complete
closures copied to a fresh local binary cache using zstd level 3; they are not
network timings. Full planning here means the default SDK/native-tool bundle,
not the SDK-only dynamic planner input closure measured in the previous round.

## Implementation and compatibility

The worker now links the selected SDK's `cmd/pack` implementation. A small patch
removes telemetry, makes its entry point callable, and closes the archive before
returning. Archive parsing, object handling, and writing remain Go's own code.
The separate 2,105,506-byte executable disappears; the worker grows by 114,688
bytes, saving 1,990,818 executable bytes overall. Archive actions retain their
existing replay syntax, and native helpers obey `NIX_BUILD_CORES`.

The new integration test compares archive bytes and verbose output against the
selected SDK's own tool. It exercises Go objects, native input bytes, padding,
long and Unicode names, executable modes, repeated operations, and state reset.
A sequence longer than the descriptor limit checks that archives are closed.
It passes locally with Go 1.25.12, 1.26.5, and 1.26.6. The Linux amd64 Go 1.26.5
compatibility suite also passes all ten cases, standalone exports, cgo/race,
custom build IDs, runtime references, cache invalidation, and dynamic builds.
Linux arm64 and Apple Silicon validation is pending the PR's CI matrix.

Fresh discovery produces identical bytes for 615 of 626 compared package
outputs. The eleven differences are cgo action IDs and dependent outputs:
Go hashes the changed native-toolchain pathname during discovery. Replaying
the original instructions with the new worker reproduces **all 256 outputs**
across those four affected cases byte for byte. Changing the worker's store path
still changes package recipes and causes a one-time rebuild.

replit/iets PR 3 at `69883a64bfb0d9a95dce253dae304878e07b076e` passes outer and
nested evaluation/builds, direct dynamic output builds, repeat builds, embed
invalidation, optional tests, and runtime-reference cases. IFD, classic fallback,
and tracing caches are disabled. This round uses iets for functional validation;
it makes no evaluation-speed claim.

## Reproduction

Use the baseline and implementation toolchains/exports with:

```sh
python3 scripts/benchmark-pack.py --before /nix/store/BASELINE-toolchain --after /nix/store/CURRENT-toolchain --runs 5 --iterations 100
python3 scripts/benchmark-closure.py --before /nix/store/BASELINE-toolchain --after /nix/store/CURRENT-toolchain
python3 scripts/benchmark-build.py --before /path/to/before/assembly-export --after /path/to/after/assembly-export --runs 5
```

Helper derivation paths, commands, and all timing samples are in the raw report.
