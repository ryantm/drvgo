# Discover cgo builds without fetching native worker tools

Measured on Linux amd64 with Go 1.26.5 on November 11, 2026. The baseline is
`040ab62ee05d010f26db3805ec03138a4095dab9`; the implementation is `6eab0dd`.
[Raw measurements and validation evidence](ci-round8-2026-11-11.json) include
complete planner input roots, timing samples, and package-identity comparisons.

## Planner inputs

Dynamic planning now uses only the Go SDK for discovery, including when cgo is
enabled. The pinned Go dry run emits native compiler probes for workers to
execute. Compiler-version queries used by cmd/go's original action IDs no longer
affect drvgo recipes, because the preceding build-ID change derives those IDs
from actual resolved worker inputs.

The generated graph still selects the same compile, link, and native bundles.
Raw worker derivation recipes remain planner inputs so the recursive evaluator
can register dependencies without first realizing every worker bundle.

Complete planner input closures, including source and derivation metadata, copied
to a local binary cache with zstd level 3:

| Workload | Measurement | Before | After |
| --- | --- | ---: | ---: |
| 67-package cgo fixture | Compressed bytes | 246,075,472 | 124,269,229 |
| | NAR bytes | 803,901,536 | 418,882,120 |
| | Store paths, including recipes | 989 | 962 |
| 554-package UPM, fixed module proxy | Compressed bytes | 438,861,190 | 317,054,947 |
| | NAR bytes | 1,038,115,216 | 653,095,800 |
| | Store paths, including recipes | 990 | 963 |

Both save **121.8 MB compressed** and **385.0 MB of NAR data**. That is **49.5%**
of the fixture's compressed planner inputs and **27.8%** of UPM's, whose closure
also contains the fixed module proxy and application source.

These are input-closure sizes, not network timing measurements. They matter when
a CI worker must fetch planner inputs before discovering that package outputs
are already cached. A native package that actually needs compilation still
requires its native worker tools; that download is deferred until needed.
The Go SDK remains necessary for discovery. Explicit `cgoEnabled = false` already
used SDK-only planning and does not gain this reduction.

## Warm CI performance

Five alternating UPM trials, with a fresh planner each time and tools, proxy,
sources, and compiled package outputs available:

| Measurement | Before | After |
| --- | ---: | ---: |
| Evaluation + realization | 3.435 s | 3.392 s |
| Outer evaluation | 0.395 s | 0.401 s |
| Realization | 3.035 s | 2.992 s |

The small difference does not establish a substantial warm-build speedup. The
main benefit is reducing prerequisite inputs. All before/after trials resolve
to the identical UPM package output, so this change preserves cached package
artifacts. It changes planner recipes without changing worker recipes or sizes.

Warmup is excluded. The timing benchmark ran alone, after correctness tests and
before the UPM closure copy. Strict sandboxing, IFD-disabled planning, four jobs,
and two cores are used; remote cache queries are disabled equally on both sides.

## Validation

The full local Go 1.26.5 suite passes, covering native builds, cgo, C++, assembly,
test binaries, race mode, custom IDs, runtime references, source invalidation,
and matching standalone/dynamic outputs. Additional dynamic C++ and explicit
external-link builds share the corresponding standalone outputs. Those checks,
plus the macOS framework case, are included in the platform compatibility matrix.

Offline external-cgo module-cache tests pass under all three supported SDKs.
Go 1.25.12 and 1.26.6 also pass iets PR #3 outer/nested builds of that fixture.
The full iets suite passes on Go 1.26.5, including direct dynamic outputs,
optional tests, and runtime-reference closure checks. Fallback and tracing cache
are disabled; integration timings are not benchmark claims.

A direct SDK-only versus full-toolchain export of the cgo fixture produces
identical recipes for all 67 packages when evaluated with the same worker bundles.
The platform matrix remains the merge gate for Linux amd64/arm64 and Apple Silicon.

## Reproduction

Instantiate each revision's `.planner.drvPath`, then measure its actual inputs:

```sh
nix-instantiate --eval --raw --read-write-mode \
  --extra-experimental-features 'ca-derivations dynamic-derivations recursive-nix' \
  --option allow-import-from-derivation false --expr \
  '((import ./nix/dynamic.nix {}) { src = ./tests/fixture; }).planner.drvPath'

python3 scripts/benchmark-planner-closure.py \
  --before /nix/store/baseline-planner.drv \
  --after /nix/store/modified-planner.drv

python3 scripts/benchmark-ci.py \
  --before /path/to/baseline-checkout --after . \
  --source /path/to/pinned-upm --package ./cmd/upm \
  --vendor-hash 'sha256-A4CU4C5SmEZP6Q+CVHjp+Jy4UxRXAnpvhzrsdq4NlsM=' \
  --nix-option sandbox true --nix-option substituters '' \
  --nix-option always-allow-substitutes false --runs 5
```

UPM is pinned to `35a76c282507fb942445c0ee98427b3d1ef772bc`; iets is pinned to
PR #3 revision `69883a64bfb0d9a95dce253dae304878e07b076e`.
