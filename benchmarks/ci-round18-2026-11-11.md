# Direct replay-script rendering, November 11, 2026

This round reduces allocation volume while rendering `scripts.nix`. Baseline
`dc3f6e0` includes reusable snapshot buffers; implementation `2594aff` writes
replaced script text directly into the final output builder. It emits the outer
quotes separately, avoiding complete quoted and replaced intermediate strings.
Escaping still precedes dependency interpolation. Generated bytes, Nix string
contexts, source selection, package recipes, and worker tools stay unchanged.
[Raw measurements and validation](ci-round18-2026-11-11.json) accompany this report.

## Isolated renderer

A profile attributed about 24% of exporter allocation volume to `nixScripts`.
The isolated comparison renders an existing prepared-UPM graph using Go 1.26.5
and four Go threads. Seven alternating trials plus warmups run twenty iterations
per invocation. Every invocation first checks exact equality with the baseline
`scripts.nix` file. Medians are:

| Measurement per render | Before | After | Reduction |
|---|---:|---:|---:|
| Time | 15.751 ms | 15.044 ms | 4.5% |
| Allocated bytes | 38,269,071 | 22,907,288 | 40.1% |
| Allocations | 48,018 | 45,534 | 5.2% |

This excludes Go discovery, Nix evaluation, and builds. The benchmark source,
commands, environment, and individual measurements are retained in the JSON.

## Whole exporter

Ten iterations of `BenchmarkGenerate` per revision, with four threads, prepared
modules, and the same compact planning toolchain, reduce allocated bytes from
140,965,538 to 125,764,888 per export (10.8%). Allocation counts change from
498,204 to 495,722. These counters measure cumulative allocation volume; combined
process-tree peak memory was not measured. Fixed-order timings from this check
are excluded from performance claims.

Separate executable comparisons use seven alternating trials plus warmups at
each thread count, with the same explicit full toolchain and prepared modules.
Replacing an existing export is included. All 48 runs have byte-identical
`graph.json`, `evaluation.json`, `scripts.nix`, and resolved toolchain metadata,
including source hashes.

| Go threads | Before | After |
|---|---:|---:|
| 1 | 0.640 s | 0.628 s |
| 2 | 0.501 s | 0.504 s |
| 4 | 0.449 s | 0.445 s |

These small differences vary with thread count. Raw `wait4` maximum-RSS values
are included for completeness and do not measure a simultaneous process-tree
peak.

## Complete warm CI

Seven alternating trials plus warmups force fresh dynamic planners with warm
tools and compiled Go package outputs. Totals include outer Nix evaluation and
realization, nested planning, and final forwarding. Sandboxing is enabled without
fallback; IFD, substituters, and forced substitutions are disabled. Nix uses four
jobs and two cores per job. Nested iets is the static build of upstream PR #3 at
`69883a64bfb0d9a95dce253dae304878e07b076e`, with one worker and both caches and
fallback disabled. All 128 runs preserve the output for their workload.

| Workload | Nested evaluator | Before | After |
|---|---|---:|---:|
| fixture | Nix | 0.857 s | 0.857 s |
| fixture | iets | 0.658 s | 0.664 s |
| UPM proxy | Nix | 3.364 s | 3.369 s |
| UPM proxy | iets | 2.971 s | 2.993 s |
| UPM prepared modules | Nix | 2.466 s | 2.477 s |
| UPM prepared modules | iets | 2.049 s | 2.051 s |
| UPM prepared modules and previous plan | Nix | 1.298 s | 1.294 s |
| UPM prepared modules and previous plan | iets | 1.160 s | 1.175 s |

The range is 0.4% faster to 1.3% slower. Treat full CI latency as effectively
unchanged; this change's measured benefit is lower allocation volume and faster
isolated rendering. Cold compilation and network transfer timings are excluded.

UPM is revision `35a76c282507fb942445c0ee98427b3d1ef772bc`, package `./cmd/upm`.
Each exact invocation is in the JSON. For example:

```sh
python3 scripts/benchmark-ci.py --before /path/to/baseline --after /path/to/current \
  --source /path/to/upm --package ./cmd/upm --runs 7 \
  --vendor-hash sha256-A4CU4C5SmEZP6Q+CVHjp+Jy4UxRXAnpvhzrsdq4NlsM= \
  --module-cache /nix/store/your-prepared-module-cache \
  --before-iets /nix/store/your-iets --after-iets /nix/store/your-iets \
  --nix-option sandbox true --nix-option sandbox-fallback false \
  --nix-option substituters '' --nix-option always-allow-substitutes false
```

Add `--previous-plan /nix/store/your-previous-plan.drv` to supply the same existing
plan to both revisions.

## Dependency size and correctness

Complete fixture planner inputs add 616 NAR bytes and 3,733 bytes in fresh local
zstd-level-3 caches. Path counts remain 964 with nested Nix and 909 with nested
iets. Worker toolchains and Go package outputs are identical.

Unit tests and vet pass. Renderer tests evaluate the generated Nix and compare
both text and dependency contexts, including compile-interface selection,
Unicode, shell interpolation, quotes, and unknown token-like text. The focused
iets suite passes public helper use, ordinary and compact archives, early cutoff,
embed edits, new dependencies, invalid source, and empty-test validation. Outer
iets with one and four workers agrees with Nix. Linux amd64/arm64 and Apple Silicon
CI across the supported SDKs remains the merge gate.
