unchanged from `cbf256621f27a310df75d1a11466b11fa0f26045` (PR #20); benchmark
script revision `6db4762ef69bbd818f4d6bcdfa55fbe5c2594803`.
[Raw samples, exact commands and policy diagnostics](ci-round14-2026-11-11.json).

## Choose a client that forwards the requested settings

At iets PR #3 revision `69883a64bfb0d9a95dce253dae304878e07b076e`, regular
`iets build` deliberately sends no daemon settings. It warns that options such
as `substituters`, `always-allow-substitutes`, `max-jobs` and `cores` are ignored.
Its classic `iets nix-build` command forwards them through `SetOptions`.
The [pinned settings reference](https://github.com/replit/iets/blob/69883a64bfb0d9a95dce253dae304878e07b076e/docs/reference/settings.md)
and local command logs document this distinction.

This matters for short CI helpers. The test host has `sandbox = true` and
`always-allow-substitutes = true`. The latter overrides derivations' cache hints,
so fresh planning and forwarding derivations can incur remote cache queries.
A diagnostic with nested static iets, three alternating trials plus warmups,
measured these complete fixture builds:

| Frontend and policy | Median |
| --- | ---: |
| Nix, explicit local benchmark controls | 0.634 s |
| Nix, daemon defaults | 7.763 s |
| Regular `iets build`, supplied controls ignored | 6.593 s |
| Classic iets, 1 worker, explicit controls | 0.528 s |
| Classic iets, 4 workers, explicit controls | 0.536 s |

The daemon-default rows deliberately use a different cache policy. They are
not an evaluator-speed comparison or a universal latency claim. Nix itself
shows the same multi-second delay with daemon defaults; a slow regular iets
build here is not evidence of slow evaluation. No host configuration was
changed. All rows produce the identical Go package output.

For CI using this pin, this invocation honors drvgo's cache hints while still
allowing reusable package outputs to be fetched:

```sh
IETS_NIX_FALLBACK=never IETS_CACHE=false IETS_WORKERS=1 \
  "$iets/bin/iets" nix-build /path/to/project.nix --no-out-link --store daemon \
  --option allow-import-from-derivation false \
  --option always-allow-substitutes false
```

Enable the dynamic Nix features using the configuration already documented in
the README. Classic mode at this pin rejects `--extra-experimental-features`
and `--no-tracing-cache`; both were checked with fallback disabled, so they
cannot silently run Nix instead. `IETS_CACHE=false` disables both the tracing
and compiled-file (IR) caches. The benchmark below uses that same setting.

## Same-policy comparisons

The new `scripts/benchmark-client.py` compares complete `nix-build` and classic
iets frontend processes, each including evaluation and realization. Every
client uses the same explicit daemon transport, strict sandbox, IFD disabled,
four jobs/two cores, and command-local cache settings. There is no change to
compiler or worker code in this round.

Five alternating trials plus excluded warmups, with warm tools, modules and
Go package outputs. A unique forwarding name forces a fresh planner each time.
Both iets evaluator caches and fallback are disabled. All clients return the
same Go package output for each workload and nested evaluator configuration.

| Workload | Nested evaluator | Nix frontend | Classic iets, 1 worker | Classic iets, 4 workers |
| --- | --- | ---: | ---: | ---: |
| Cgo fixture | Nix | 0.820 s | 0.753 s | 0.620 s |
| Cgo fixture | Static iets | 0.634 s | 0.531 s | 0.519 s |
| UPM, module proxy | Nix | 3.392 s | 3.374 s | 3.189 s |
| UPM, module proxy | Static iets | 3.170 s | 2.891 s | 2.803 s |
| UPM, prepared modules | Nix | 2.700 s | 2.456 s | 2.301 s |
| UPM, prepared modules | Static iets | 2.339 s | 1.899 s | 1.881 s |

These are complete single-process frontend timings. They are a separate
measurement from the two-process evaluation/realization breakdown produced by
`benchmark-ci.py`; compare clients within a row. They do not measure cold
compilation, cold-store transfers, or the speed of normal `iets build` under
a different daemon policy.

## Reproduction

```sh
python3 scripts/benchmark-client.py --iets /nix/store/...-iets/bin/iets \
  --source tests/fixture --nested-iets --runs 5 \
  --nix-option always-allow-substitutes false --nix-option substituters ''
python3 scripts/benchmark-client.py --iets /nix/store/...-iets/bin/iets \
  --source /path/to/upm --package ./cmd/upm \
  --module-cache /nix/store/...-drvgo-module-cache --nested-iets --runs 5 \
  --nix-option always-allow-substitutes false --nix-option substituters ''
```

Omit `--nested-iets` for the default nested Nix evaluator. Replace
`--module-cache` with `--vendor-hash` for module-proxy trials. Disabling
substituters is only for isolating local costs when inputs are already present;
normal CI should retain its configured binary caches. Exact source pins, cache
paths, evaluator package, commands and every sample are recorded in the JSON.

The script passed a smoke run and all six full benchmark scenarios, including
output-identity checks across clients. This round changes only the benchmark
script and documentation; PR #20's runtime code passed all 11 platform/SDK
checks before this follow-up.
